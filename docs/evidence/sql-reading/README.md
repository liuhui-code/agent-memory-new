# Nonexclusive existing SQL-candidate source reading

This is a source-display capability, not a SQL/UI pair certificate, business-domain attribution, unique-target claim, or proof of database execution. It does not broaden `sql_slot_request` or call the whole-scope pair qualifier. Existing candidates, ranking, graph, logs, and source bodies remain unchanged; only additive expansion bodies and accurate excerpt counts / budget estimates change. The literal SQL forwarding helper may return `[]`; the display explicitly marks execution, pairing, requested behavior, and domain as unverified.

## Freeze and implementation order

1. `protocol.json` froze eight independent positive requests, twelve negative requests, and two source fixtures before parser / serving implementation. These are developer fixtures, not independent real projects, holdouts, or Agent accuracy trials. Requests and sources were not rewritten to obtain passes.
2. `additional-source-controls.json` contains concrete unknown-callee, unsupported-argument, fake-SQL and shadow-helper controls. These were frozen after initial implementation but before their first execution. Their timing differs from step 1.
3. Initial unit run (`tests-first.txt`) had a test-harness error: its convenience helper converted explicit `None` back to a default payload. Direct malformed-input testing corrected the test, not the product. Initial independent CLI outputs are retained under `initial-controls`; these predate `domain_unverified` and are not the final candidate's token results.
4. Original 06 first replay (`original-v1`) remained 2/3. The candidate demanded a raw `code_anchor` for every callable. The existing raw/compact `ShortcutSearchPage.build` alternative had no raw anchor, so processing aborted before appending the SQL body. No source or scoring input changed.
5. The v2 correction permits an already-present raw **and** compact callable candidate without a raw anchor, but still requires unique current DB method/container identities, qualified name, source range, symbol key, generation, and source digest. If a raw anchor is present, its typed ID and source identity must also match; ambiguity fails closed. This is not new candidate discovery. A regression covers the missing-raw-anchor case.
6. Final same-version independent CLI comparisons (`final-controls`) run each frozen request twice from fresh copies of the same seed: current runtime with only this terminal hook disabled, and current candidate. All previous records and original v1 results remain retained.

## Bounds and fail-closed controls

Whole-request ASCII grammar requires positive SQL-source reading, with narrowly parsed optional observations retained as unverified constraints. It does not delete quoted, negative, comparative, only/instead, or trailing clauses. Unknown requests do nothing. Source validation uses at most eight existing callable candidates, bounded active typed rows, current owner and helper declarations, current file bytes, digest/generation, and snapshot state. Complete bodies are limited to 40 lines / 1500 characters each and 2600 excerpt characters total. Existing primary/expansion/file limits and original 1500 / 2000 budget remain unchanged. All new matching positives must fit together; otherwise no-op. Fully covered bodies are not duplicated.

Commands and raw JSON are in each evidence subdirectory. Recorded absolute workspace paths are execution provenance, not portable prerequisites. Repo tests use the two repo-local frozen protocol files. `artifact-hashes.json` records retained evidence bytes. The final-controls first wrapper failure (`final-controls-first.log`) was a report-restoration assumption that every output had `source_excerpt_policy`; preserving absent keys fixed that wrapper, with no product change.
