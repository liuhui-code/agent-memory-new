## Confirmed before and proposed implementation contract

Frozen source executed with Node: catalog refreshed. Both public modes report
unrelated east-region; path run→refresh→logger.info remains correct. Before
summary retained; full raw stdout kept in the private delivery archive.

Propose a narrow single-hop binding, no generic dataflow or ranking change:
- Only static_wrapped depth1 calls with current typed caller/wrapper/sink identities,
  same file, matching nonempty source digests and generations, and same nonempty
  declared owner; caller must use this.exactMethod. Inferred/external receivers,
  multi-hop, aliased log APIs and unsupported syntax receive no new certificate.
- Wrapper complete current method range must fully match ordinary typed scalar
  parameters (unique ASCII identifiers, no optional/default/rest/destructure),
  optional void PARAM no-op statements, then exactly one canonical API call with
  its message expression exactly one parameter, then method close. No assignments,
  shadowing, branches, aliases, arbitrary extra statements, nested closures or
  template interpolation. Method name and sink raw statement must match indexed
  identity/source. Literal fixed/template sinks retain their existing protection.
- Bind the message parameter position to the same ordinal complete call argument.
  Accept only complete simple quoted literals without escapes or interpolation;
  require all arguments to be simple literal/identifier/numeric expressions and
  exact arity. Never assume ordinal2 or a parameter name means message.
- A direct parameter sink with unavailable or unsafe binding must use its existing
  symbolic sink template, not mint a business literal. Unsupported existing paths
  outside direct same-owner/static depth1 scope keep legacy behavior explicitly;
  this is not a claim that those old effects are all source-proven.
- Protect typed identity, source digest/generation, path, raw caller, range and
  budget metadata. Read bounded complete source bytes once per file per rebuild;
  missing/drift/unknown cannot produce a new concrete binding.

## Independent review corrections, before final acceptance

The initial candidate's shared bounded reader broadened the new2MiB/UTF8 refusal
to old raw_call extraction. Review rejected that: legacy caller reading now keeps
its existing whole-file read/ignore-decode contract; the same bytes are reused for
new proof only if <=2MiB and strict UTF8. One existing read/file is shared; no extra
new-proof read occurs. Large/invalid legacy raw_call controls compare exactly to
the original call_message route. This is a bound on the NEW binding authority,
not a newly imposed global file-reading limit. New proof-only reads stay bounded.

Review also added class digest/generation/qualified identity checks, same-line
field receiver shadow refusal, ordinary method types, conservative reserved words,
and an actual semicolon/newline requirement for void PARAM no-ops. Unsupported
syntax does not prove a literal binding. Binding reuses existing sink classification;
it does not establish arbitrary Logger implementation behavior.

edge, but the actual producer supplies zero edges. Preserve the failed run and
