# Listener optional batch and source-slice list experiment

Base b6d958b. Docs-only disposable overlay; no tools/tests/production edits.
The new CLI list diagnostic is useful beyond the pre-existing raw side column:
it checks current project-root source bytes/digest, declared row identity and
witness source slices, or reports unknown. It does NOT reparse full qualified
owner identity or prove dynamic binding, runtime dispatch, request satisfaction,
uniqueness, or absence. Provider metadata remains trusted at its documented
boundary. No offline name-association is silently promoted to runtime evidence.

## Limits and caps

Batch list type/count <=64 is checked before item iteration; encoded whole
optional list <=65536 bytes before per-item validation. Exact duplicate facts
are normalized in original order. Same source key/digest/invocation interval
with differing payload rejects the optional batch, not legacy metadata.
Only method/function entity kinds qualify. This remains an experimental schema
and model protocol, not a production-ready change.

Storage retains the old mechanism JSON byte-for-byte, optional JSON uses only
remaining space within4096 bytes. Diagnostic values use a separate cap: <=64
inspected rows, each value <=4096 encoded bytes and the JSON ARRAY OF VALUES
<=65536 bytes. This does NOT include field keys or old row contents and is NOT
a cap on entire list output. Omitted diagnostic fields mean uninspected; no old
row is removed. Raw list is not claimed to fit1500 tokens. Compact is unchanged.

Source reading uses safe_source_path under the current fixture project root,
reads at most32769 bytes and rejects >32768. Absolute/escape/symlink paths are
unknown; external learn-path roots are unsupported here, not guessed. Raw digest
and normalized character coordinates remain separate. The source validator
reuses the existing prototype; it is not an independent full parser or owner
scope proof. Missing/empty/capped/old-index payload means unknown, never zero
implementations. Partial-domain uncertainty and unresolved request qualifiers
remain explicit even on a source-slice-positive record.

No original failure count improvement, no full gate, no serving promotion.
