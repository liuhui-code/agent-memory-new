# Output read-loop rebuild protocol

Baseline 066cc1a (production fced64c4). NEW implementation; missing historical
8b2c304 commits and their test results are not recovered or reused as acceptance.
The unchanged independent PipeCollector protocol is copied byte-for-byte from
output-loop-followup/protocol.json. Run normal public init/learn/context raw+compact
for its three fixed requests, and the original process-output-read-loop-owner
Development group only. No aggregate/holdout; unchanged source/query/oracle.

Candidate qualification must prove a direct finite same-method source shape:
parameter receiver readLine into local cursor; null-checked while; same cursor
pushed into local empty string array; same receiver re-read; same array joined as
return. No arbitrary marker conjunction, callback/deferred operation, after-loop
push, swapped receiver/cursor/array, or read-once may qualify. Whole parsed file,
original byte digest, indexed method range/owner/ID and current generation bind
source receipts. Unknown syntax is unknown, not absence.

Positive source witness does not alone grant selection. Request must explicitly
ask for iteration/read-loop AND accumulation/collector of output, with literal,
quoted, named or multiple-role/conflicting requests falling back. Do not loosen
ordinary scope or classify descriptive literal methods as impossible. Preserve
logs/graph/path obligations and existing 1500/2MiB/source budgets. Fresh finalized
compact must contain all selected method text or transactionally use old context.
Freeze request and source controls before implementation; report any changes to
this protocol and candidate failures. No source/query padding to chase green.
