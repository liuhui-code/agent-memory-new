# P1 评审尺度校准：已知材料自审

日期：2026-11-18。材料为已完成的 [P1](../../design-preview-development-case.zh-CN.md)，
当前 Agent 同时是设计作者；非盲法、非独立评审、非新任务，不进入任何效能分母。
本记录检查工作表能否区分“当前行为成立”“有依据的取舍”和“尚不能判断”。
没有 A/B/C 的真实运行产物，下面不评三组胜负。

| 问题 | 已有证据与判断 | 限制 / 不可迁移部分 |
|---|---|---|
| 输入是否改变了设计？ | 核对 `review_server.py` 的线程入口后，采用同一锁内的身份检查与发布；未直接复制 M1 的串行提交机制 | 夹具没有接入该服务器；入口事实不等于生产集成已验证 |
| 边界是否清楚？ | [Coordinator](../../../tests/fixtures/design_preview/preview.py) 不做渲染/数据库/线程调度；状态提交集中，回执用对象身份限定当前实例 | 不解决 HTTP/点击顺序、跨进程身份和访问权限；不能把局部边界称为完整预览架构 |
| 当前行为是否有支撑？ | [最终记录](../design-preview-development-20261117/final-contract-checks.json)为 14 个受控检查；含过期/取消/重复/其他实例、失败恢复和特定线程交错 | 不是所有交错、负载或真实宿主验证；通过只覆盖声明范围 |
| 抽象是否必要？ | 两种格式使用普通函数和共同输入/输出；当前没有策略注册表或队列生命周期负担 | “类更少”不证明更好；有既有队列/插件机制的宿主可能选其他方案 |
| 变化是否保持局部？ | 输入已提前指定增加 JSON；实际只改 renderer/测试，103 行 owner 摘要不变 | 只支持这一项格式变化；没有额外维护者改动成本或未来变化分布的数据 |
| 参考是否被审查？ | [参考审查](../design-preview-development-20261117/reference-review.json)保留 M1 部分适用与 Stop 语义失配；Strategy 采用函数边界，不照搬类层次 | 目录的 ATAM 链接不是直接模式定义；参考准确性缺口仍保留，不能用命中名称认证设计 |
| 负例是否构成比较？ | 已知错误原型暴露旧结果覆盖与可变输入问题，可用于检验行为验收能否识错 | 它是故意错误控制，不能称现有 Agent 的正常基线或独立候选胜负 |
| Memory 是否有增量收益？ | 手工种入的 M1 记录被引用，当前 Agent 声明部分帮助 | 无不使用记录的同条件对照；C−B 为 inconclusive，不能把声明当测量 |
| 指导是否有效率收益？ | 产物说明了前提、拒绝理由、一次变化和反馈条件 | 无 A/B、无完整任务 Token/耗时与独立返工数据；B−A 为 inconclusive |

综合判断：对已声明的开发夹具范围，可接受其行为与边界证据；真实产品适用性仍待设计。
“正确的书名”“检索到 Strategy”“103 行没变”“14 项通过”都不能独立转化为设计品味或收益分数。
本轮不重跑这 14 项，也不重算为新增检查数量。

用同一尺度做三个已知主张的校准：

- “取消后旧回执不能提交”：有受控测试和状态边界支撑，在声明范围接受。
- “因此取消会终止渲染线程”：与原契约不符，拒绝；不可用通过测试替代这个不存在的保证。
- “因此 Memory 比普通 Skill 更能改善设计”：缺对照和独立结果，保留 inconclusive。

工作表可据此留下具体的接受、拒绝和未知；没有发现需要新增 Runtime 判断器的共同缺失契约。
后续先补真实来源和独立评审，不以扩展模式数量或自动打分来关闭这些未知。
