## Minimal contract proposal for review, not implementation approval

Keep retrieval evidence about earlier actions available. Distinguish an explicit
historical/background clause from the current retrieval target *before granting
exclusive narrowing authority*. Mere lexical occurrence of a symbol in background
text should not itself certify that symbol as the current requested owner.
True method requests, actual literal/log requests, ambiguous clauses, quotations,
multiple targets and unknown grammar must not be reinterpreted by a broad token
removal rule. This proposal does not prescribe deleting `load`, suppressing logs,
changing scores, or retaining all uncertain candidates. It also does not claim the
current heuristic boundedness already supplies a semantic attribution certificate.

There is not yet a tested parser/representation to implement this distinction.
A follow-up would need an independently frozen syntax/attribution contract with
positive, negative, ambiguous and multi-target controls before any serving change.
That is a separate approval decision, not an invitation to tune this input.

The scroll `current code owner` red concerns task-metalanguage versus domain code.
This experiment concerns a genuine domain action assigned to historical context.
They share a downstream lexical-localizer symptom, but this does not establish
that one bounded grammar/representation resolves two independent defect classes.
Do not automatically count them as satisfying the architecture gate. Stop here.
