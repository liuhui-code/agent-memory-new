# Stage E: terminal code presentation transaction (design, not implementation)

B's missing pool and D's nonempty raw-log guard failures remain failures. C is a prerequisite candidate, not an independently accepted fix. No old guard is modified. This new finite presentation contract retains the original 13 inputs and Stage B exact request/source grammar. Four C pool-qualified relationship cases are the proposed targets; the two bare accumulator cases stay baseline, with their misses visible. Seven no-authority cases preserve C baseline exactly.

## Transaction

Obtain the ordinary fully compacted baseline first. Raw context remains byte/object-equivalent to its ordinary baseline. Construct a deepcopy of compact; never rerun compact_handoff, output-loop formatter or enforce_budget. A successful transaction replaces only the explicit code view with every source-qualified positive in the original bounded pool. This is lossy code selection, not absence/uniqueness or runtime causality. It does not discard log or path evidence.

Allowed paths, and no others:
- query_handoff.code_anchors: complete typed positive methods and full snapshot bodies, existing limits.
- query_handoff.callable_evidence: code-only retrieval evidence; must not contain or overwrite log/path evidence. Certainty is non-exhaustive, not unique.
- query_handoff.source_excerpt_policy: existing policy shape with source snapshot label, body_persisted=false, excerpt_count/excerpt_chars; no limit increases.
- evidence_gaps: recompute only `no_code_anchor` and `limited_code_anchor_diversity` using existing code file-count rules; preserve other strings and their relative ordering.
- sufficiency.status, next_action, reason_codes, coverage.source_locatable_code_anchor: recompute with existing diagnosis_sufficiency on the resulting handoff, unchanged freshness and resulting gaps. All remaining sufficiency fields, including log/path counts, must equal baseline.
- output_budget.estimated_tokens: existing estimate fixed point; target_tokens and truncated retain baseline values.

Every other nested value is deep-equal, notably log_anchors, path_context, log_keywords, relation_hints, source_exploration, experience/semantic refs, next_queries, role boundary, corrections and freshness. Unknown fields are preserved, never dropped. Compare a restored-whitelist copy to baseline before commit. Any mismatch, token overflow, line/character/window/positive capacity failure returns the identical baseline object. No post-commit trim.

## Binding and protection

Use the previously reviewed source digest/generation/typed method and owner row checks, full source parser and same-request private capability; copied/raw/serialized/mutated payloads cannot grant authority. Initial bounded pool only, no second recall. Named source in either original context or head remains protected, case-insensitively, using existing exact identity evidence. Source-name WORD slots are not a bypass. All qualified positives must fit.

Active or wrapped path, graph-associated candidate, explicit log/event intent or matched log/event identity, or uncertainty about those protections gives whole baseline. Nonempty raw/compact logs alone do not prohibit E, because both entire log objects are independently preserved. Never infer that empty compact logs mean raw logs were absent. Old D protected() remains unchanged. Exact proposed identity predicates: any event_match(log, original_query).priority > 0, independently_named_log_owner(log, original_query), or identity_match/log_identity_match/graph_neighbor/graph_relation on any baseline source anchor forces fallback. Query-to-source explicit matching additionally checks path, symbol and qualified_name case-insensitively across the original bounded pool, including context WORD slots. Raw path activated/wrapped_log_evidence or nonempty path_candidates/seeds forces fallback. Missing/malformed protection inputs fail closed. No score thresholds change, and no log is reclassified weak.

## Preimplementation checks

One saved-payload copy capacity diagnostic for the four eligible cases, clearly hypothetical and not public after. It verifies only representational capacity and non-code equality, not authority or selection success. Preserve raw and compact separately. No other original contexts are run for this diagnostic.

One independently frozen public preservation control: use the existing old-source-relation source bytes unchanged and request `Locate AfterIteration.summarize and the console log source for chunk.` This is explicitly a protected request, not another positive contract request. Record actual compact logs; if nonempty, verify exact fallback retention. If empty, report uncovered public nonempty-log branch without resampling words or changing source. Do not claim fallback demonstrates successful-transaction log preservation.

Helper-level transaction controls inject nonempty compact log/path/relation objects into a finalized baseline: successful code transaction must preserve all those objects exactly; any unauthorized nested mutation, budget overflow or source/binding failure must return the original object. These are internal invariant tests, not public evidence. Separate protected active/wrapped/graph/named-log controls require fallback. Test copy/mutation, full-positive count, stale/missing identity, modified source, raw immutability, and final usage exactly once.

No public new run or runtime implementation before independent review of this design and the capacity result. If code-derived status cannot be updated within this whitelist or an existing receipt is not sufficient, stop and report rather than broaden it silently.
