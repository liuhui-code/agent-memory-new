## Reject the broad hypothesis

`Return the current code owner.` cannot be unambiguously categorized by syntax
alone: code may denote a domain entity whose owner is requested. Likewise `Find
implementation owner` can name a domain role. Do not remove code/owner/implementation
globally, blacklist a generator, amplify layout labels, or override target scope.
No generic safe transformation of the original failing paraphrase is claimed.

## Small hypothesis worth falsifying, not already accepted

Only an independent single imperative command at query start:
`find|locate|show|return [the] source code for|of <nonempty remaining target>`.
This exact common grammatical noun phrase has a task-language reading distinct
from the following target. Token spans, rather than the token spelling `code`,
would be attributed: `source code` before the delimiter is request metadata;
all words after `for/of` remain ordinary domain/identity evidence. A domain code
occurrence in the tail must therefore survive unchanged. The unchanged original
query remains the input to scope, explicit identity, exclusions and typed/source
certificates. No target permission or certificate may be created by the annotation.

This is English-only, not a new language-specific semantic claim. A sentence with
quotes/backticks, explicit literal/text intention, an exclusion, multiple targets,
more than one command/sentence, or unsupported prefix is an identity transform.
Those vetoes must use original query evidence, not normalized retained terms.
No fallback guess. Owner, source and implementation alone remain unchanged.

Before any runtime implementation, use a standalone experimental projection to
show exactly which character spans are marked and what unchanged domain terms
remain. If doing so requires authorizing a broad generic-term stopword or changing
scores, reject rather than implement. No production helper is proposed yet.
