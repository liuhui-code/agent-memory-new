# Prospective positive Builder declaration selection

Base acd7619. Development. Design only: no consumer implementation yet. Existing
arkts_builder producer is accepted; this proposes its first narrow consumption
contract, not repair of a previously promised fine-grained consumer. Historical
notes mention two rejected grammar attempts, but their source/protocols were not
recovered from current Git/shared workspaces. Their results are not reused.

## User-visible failure and finite requested output

Keep the existing independent three files and five queries byte-for-byte. The
known generic request chooses instructional LayoutGuide rather than the actual
RibbonCanvas.renderStrip; exact method, ordinary layout, both explicit components
and text controls pass. Refresh this before on current base without changing it.

Proposed authority is positive and non-exhaustive: a complete request whose head
explicitly asks for a Builder declaration may select known arkts_builder callables.
It does not classify unmarked callables as non-Builder, certify completeness of the
index, prove layout effects or claim a globally unique implementation. No supported
positive or any identity/request conflict means unchanged old behavior. Multiple
known Builder identities cannot be collapsed by display diversity or forced unique.

## Initial complete request grammar for review

English only, single sentence, exact full-string consumption, optional final dot:
`(Find|Locate|Identify) (the|a|an) (reusable|declared)? (@Builder|Builder)
 (declaration|method|function)? [that (sets|configures) ATTRS]`.
Without the relative clause the role noun is the entire output target. ATTRS is a
comma/and-separated list of one- or two-word lower-case noun labels. The grammar
must reject reserved grammatical words (prepositions, determiners, auxiliaries,
negators, conjunctions other than list-and), quotations, backticks, digits, paths,
qualified identifiers, clause punctuation, capitalized/explicit names and trailing
unconsumed text. Attribute labels are retrieval description ONLY, never evidence
that a Builder performs the action. No property vocabulary from the original case
is introduced and no source behavior certificate is fabricated. This bounded
surface accepts the retained independent row-height/alignment request but does not
claim a general natural-language parser.

This grammar is a proposal to be reviewed BEFORE execution. If the reviewer cannot
justify the noun-label subset without semantic exceptions, do not implement it.
In particular textual/generated-artifact/comparison scope must not be silently
accepted as an attribute label. The suffix `in the generated source` is outside
this complete grammar, not removed before parsing. No negative-clause stripping
or generic positive_retrieval_query grants role authority. Prefix symptom clauses,
Chinese requests, plural/mixed target requests and unsupported action grammar are
initially unknown, not silently made single. Original group is measured separately;
no promise that its remaining Chinese precision failure qualifies in this subset.

Wrapper head, text head, generated-source head, quoted Builder, an explicit other
identity or mixed/multiple request must retain the entire prior serving behavior.
A real declared Builder may delegate to another Builder: no body call/delegation
ban and no deduction of direct rendering. Explicit named control remains the old
identity contract. The grammar does not need to support every form of prose about
delegation to preserve a real delegating Builder under a plain declaration request.

## Consumer location and boundaries

Use a dedicated request descriptor and dedicated positive eligibility field at the
existing full ranked-callable boundary. Do not set typed_contract_match,
source_operation_match or target_owner_kind_match, and do not alter scores or
component aliases. Match only already-produced arkts_builder on an actual typed
function/method with full source identity/range/digest. The full candidate set,
not the display alternatives, determines distinct eligible identities. Stale,
malformed/partial identity or no positive eligible role falls back to old output.

Selection may prioritize known role matches and project their existing exact
callable ranges within original limits; it must keep uncertainty/non-exhaustiveness
explicit. Multiple known matches retain existing bounded multiple evidence rather
than inventing a single winner. Existing explicit identity, graph/path/log source
protections and budgets remain. If the existing boundary cannot support this without
cross-cutting private authorization or new architecture, return for review.
Old archives without roles keep identical output; normal relearn is existing activation.

## Frozen evidence and stop

Original five cases are immutable. Additional fixture/control families must be
frozen before the first new run: generated artifact, wrapper, real ordinary
component, quoted instructional text, explicit conflicting identity, two Builders
(including same-file), one genuinely delegating Builder and unknown lexical/old
index. For no-authority requests require complete code-anchor/primary/log/path
compatibility, not merely target recall. Role-positive multiple controls require
all qualified identities to remain and no uniqueness claim. Positive declaration
selection does not grant exclusion of log/path evidence.

Stop if the frozen actual public red is absent or the positive grammar admits a
non-declaration output request. Do not adjust queries, sources or eligibility after
observations to chase a pass. Source/test implementation starts only after reviewer
accepts this design plus frozen actual before. Original23 is evaluated separately
only after candidate focused tests; no full gate or original repair claim inferred.

## Pre-execution design correction (no run has occurred)

The initial ATTRS wording incorrectly suggested a noun classifier. It is only a
finite lower-case token surface; relevance remains ordinary lexical evidence. A
Builder that renders source text can be a genuine declaration target. The frozen
artifact-label query is therefore NOT proof of artifact-output intent. It remains
unsupported in this first subset because the relative action grammar now admits
only sets/configures, not renders/arranges. This whole-action limitation applies
equally to every content noun, not a source/text word ban. Initial proposal and
protocol commits remain in history. No result/query/oracle was tuned after a run.
Generated source output-head and unconsumed suffix remain distinct controls.

Qualification is parsed from the original untouched public query, before localizer
positive_retrieval_query cleaning. It cannot be minted from a cleaned rank query.
An original unknown/negative/mixed sentence must not be turned into a positive
request. Validate source row identity before compact projection drops digest/key;
never reconstruct authority from a JSON boolean or truncated roles.

For multiple role matches within the existing bounded candidate pool, preserve
distinct method identities including same-file members. If projection cannot retain
all admitted matches within unchanged limits, retain prior behavior with uncertainty
rather than silently asserting a unique match. Non-exhaustiveness is explicit.
