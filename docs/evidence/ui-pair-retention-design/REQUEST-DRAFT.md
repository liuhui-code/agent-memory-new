# Narrower alternative: natural spelling of two declared UI identities

Review draft after b434684. No run, no implementation. This replaces, rather than
quietly broadens, the graph-authority proposal if accepted. Relationships are NOT
used as permission. Existing graph, path and log protections remain unchanged.

## Entire original request, three proposed forms

1. `Return both UI source contexts for NP and NP.`
2. `Locate the typography code for NP and NP.`
3. `NP and NP render inconsistent text sizes. Return both UI source contexts.`

Case insensitive ASCII words, normal single spaces (or hyphens INSIDE NP), final
period optional. No quotes, extra sentence, negative clause, suffix, whitespace
control, arbitrary stripped symptom prefix, conjunction other than the one shown,
or generated-output rewrite. Each NP contains 1–3 ASCII alphabetic words, with
no reserved operator words: and/or/not/only/both/except/exclude/instead/without/
return/find/locate/source/code/context/generate/instruction/call/caller/wrapper.
NP order must remain distinct; duplicate or ambiguous assignments fall back.
No attempt to diagnose the claimed text-size inconsistency is made.

## Exact content-word identity correspondence

Split CURRENT component/struct declaration names using existing identifier_parts
(or whole alphabetic identifier when it does not split). Match every NP word in
order, with no stopword omission, substring, arbitrary synonym or body/path match.
A word may match exactly or by the existing english_query_variants regular plural
rule. Both literal and regular variants are considered; if either interpretation
maps to multiple distinct declared owners, fallback rather than prefer one.
Example correspondence: product tiles/ProductTile, price labels/PriceLabel,
message rows/MessageRow, quoted-message previews/QuotedMessagePreview. These are
spelling correspondences, not graph links, role inference or semantic aliases.

Only current declared component identities may participate. Two different owners
must be already represented by complete admitted anchor ranges. Method names alone,
matching filenames without declaration, a partially matched owner, stale or missing
source identity, duplicate same-name declarations, or insufficient retained ranges
cannot grant the obligation. Verify original query and typed source identities in
one local snapshot; ordinary dictionaries or JSON must not mint permission.

The only effect is refusing a later single-primary narrowing that would erase one
of the two requested declared identities. It does NOT replace anchors, append new
source, create full-body authority, discard unrelated anchors, override budgets,
change scores or set graph_neighbor/source_operation. Missing independent public
red ends the trial; internal parser success does not authorize shipping.

## Required compatibility controls before public execution

Single owner; exact named pair; generated source/instructions; quote; negative;
extra mixed output; three requested owners; duplicate NP; another actual UI pair
with distinct names; same normalized words resolving to multiple owners; only
import/no component declaration; stale/missing identity and one endpoint not in
anchors. A natural two-source request is allowed even with no render edge: the
user explicitly asked for those two declarations, not a relation certificate.

## Approved freeze clarification before first independent execution

Reviewer accepts this NO-GRAPH contract, not the earlier graph proposal. Only
exact and the existing final-s/final-ies plural branches may be used; -ied is
explicitly NOT plural and is rejected. Irregular words are not inferred. Consider
all exact/variant matches and refuse ambiguous assignments. Uniqueness is only
within the current admitted declaration inventory, never a whole-project claim.

'Complete admitted range' means an already-existing, complete readable method or
component interval, not a requirement that both entire declaration bodies already
be anchors. Same-read declaration row, typed owner attribution, interval containment
and current digest must establish representation. A state-only anchor is not enough.
No existing interval may grow and no missing source may be added. Two distinct
owners in one file need both existing represented intervals; file count is not
owner count. Source-binding controls in protocol.json are implementation gates,
not invented successful public results. Baseline runs only the frozen public inputs.
