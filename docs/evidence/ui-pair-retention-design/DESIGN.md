## Proposed smallest new contract, not implementation approval

Only a complete request for two UI source contexts may acquire a non-exclusive
retention obligation. The obligation would preserve an already admitted, bounded
pair against single-callable narrowing; it cannot invent a source, boost a score,
exclude other anchors, grant source_operation, or mark every graph neighbor safe.
Existing source budgets, explicit path/log controls and identity checks stay.

Three gates need independent review BEFORE any implementation:
1. Full original request head recognizes exactly a two-UI-source request; quoted
   text, generated artifacts, negatives, mixed output goals and unknown suffixes
   must not be cleaned into authority. Natural role phrases are not identifiers.
2. A currently learned typed renders_component/passes_property relation binds a
   parent component and child component. Both endpoints must resolve to current
   project source identity/digest/ranges already present among admitted anchors.
   Merely sharing a file, having an import, or generic calls is not sufficient.
3. Multiple plausible pairs or unclear phrase-to-source correspondence falls back;
   one graph pair does not prove global uniqueness or runtime data flow. A retained
   pair is non-exhaustive, and serialization/copy cannot mint its private authority.

The key unresolved design choice is gate1/3 attribution. A request saying 'both UI
source contexts' alone does not identify which of several already recalled pairs
it means. Options for review:
- require an unambiguous bounded lexical association of both requested noun phrases
  to distinct current component identities, with independently frozen plural and
  compound-name ambiguity controls; this is NEW attribution, not exact naming;
- or retain all already admitted UI sources for this explicitly plural output head,
  without relation authority. This is broader and risks unrelated-source precision
  and budget; it must not be quietly substituted for the pair contract.
Neither option is authorized here, and no old grammar is modified.
