# v2 disposable listener model experiment (frozen before execution)

Base2ec802f. Only docs scripts/results, never production tools/tests/schema. Keep
prior attempt artifacts unchanged. Same20 source controls and fixed5 queries,
source bytes and oracles copied by reference/hash, no post-result tuning.

Interface choice: optional typed_invocation_witnesses list on experimental batch,
separate from SemanticMechanism. Each source fact binds exact outer key/path/full
range/signature/digest and formal/member plus normalized-character source spans.
There is NO join to descriptive operation detail, no case folding, no new query
consumer. Source producer compares its exact witness to parsed outer entity.
Decoder verifies only structure/signature/snapshot consistency from provided batch;
it trusts the producer for source parsing and cannot independently authenticate
source bytes it does not read. Source-time validation is reported separately.

Temporary runtime only: an experimental SQLite code_symbols side column transports
optional witnesses for public list/real normal merge. It is not a generic graph or
approved migration. Old install-only indexes remain unknown. Old mechanisms remain
byte-for-byte intact, their record order and search terms unchanged. Additional
side JSON uses only4096 minus old mechanism payload bytes; if even [] cannot fit,
store SQL NULL/unknown. No cap increase. Whole witness omission is unknown.

Version dispatch: experimental-v2 is explicit. Legacy v1 without any typed field
is read as legacy unknown. Legacy v1 containing typed witness fields (batch,
mechanism or entity) is rejected, not relabeled. Unsupported versions reject.
Old runtime must reject new-version exports. New exports roundtrip exactly.

Frozen additional controls:
- Signature mutation: valid-but-wrong formal index, declared type, name, duplicate
  type ambiguity; all reject against exact signature.
- Wrong coordinate unit, bool bounds, impossible nesting, outer bounds mismatch,
  source-key/path/signature/digest mismatch, unknown version and oversized payload.
- Source case collision: a single method contains object callbacks invoking both
  target.onFailure and target.onfailure on the SAME source line. Both independent
  exact-offset facts must retain case, not bind through lowercased detail.
- Legacy v1 polluted at batch, entity and mechanism levels rejects. Clean legacy
  imports no witness. Old-reader rejection explicit.
- Byte capacity: real legacy payload unchanged exactly at low/near-full/full cap;
  optional facts omitted as whole. Real typed source cannot displace old records.
- Same20 actual learn/list source-fact controls must meet unchanged expectations,
  including Native. Fivequery output differences are all saved, not tuned away.

This is not a broad dataflow framework or unique-owner authority. A finite local
adapter/model protocol is not automatically broad architecture; feasibility and
compatibility do not authorize production. Full source parsing/encoding/semantic
binding beyond the original bounded grammar remains unsupported. Reviewer sees
frozen controls before execution; all failures retained. No rank/selector changes.

Pre-execution clarification: legacy typed-field presence rejects even when null,
empty array or empty object; no unknown-field laundering. Combined budget is the
sum of UTF-8 byte lengths of the two stored JSON column values, including each
array's brackets, separators and quoting. There is no extra JSON envelope; SQL
NULL side column contributes zero JSON payload bytes. Empty side [] costs2 bytes
and is used only if it fits; otherwise side is SQL NULL. Existing legacy prefix
is generated once by the unchanged4096 cap and is never edited to create space.
No fact-order tuning. Capacity omission of an otherwise valid witness is explicitly
expected unknown in boundary controls, not a reason to change the acceptance oracle.
