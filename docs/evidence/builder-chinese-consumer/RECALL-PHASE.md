## Finite projection and integration

Parse the ORIGINAL query using the fully frozen CHINESE-REQUEST-GRAMMAR grammar,
before positive_retrieval_query. Keep exact original query and complete AST in an
immutable internal descriptor. A recognized request projects only its canonical
attribute call spellings (six-name catalog), casefolded for existing FTS lexical
matching. Original-case names remain in the AST. This is marked lexical expansion,
not explicit source identity, role authority or a source operation certificate.
Unknown/full-query conflict => no descriptor and byte-identical old path.

Supply this descriptor explicitly to the built-in SQLite recall and code-scoring
step; never append translations to the public/query string, never reparse the
cleaned query, and do not use a string subclass that silently loses its provenance.
Custom CandidateRecallPort implementations retain their existing API; default
built-in construction may take an optional descriptor without changing that port.
Pass only derived terms through optional internal parameters needed by
recall_table_candidates. Default None keeps ordinary helper calls unchanged.

Reuse method_body_fts: existing method focus terms plus distinct projected terms,
under the existing 16-term cap, existing >=2 term admission and >=2 evidence
coverage, existing recall limit and same RRF coefficient. Do not add a lane, index,
SQL table, source-role search or broaden coverage thresholds. Preserve old term
order; append new distinct terms only within remaining capacity. If capacity
cannot represent all requirements, do not apply this projection.

A recalled row must survive the existing scorer: add the projected lexical terms
only to code-source weighted matching at the already existing weights, not to
experience/log scoring or global query expansion. Keep original query for explicit
identifier checks, salience, language, negative filters and scope. Record a distinct
expanded-property match reason/provenance for rows actually matched by projected
terms; never label them explicit identity or source_operation. Existing method
coverage also uses this same bounded projected list so recall and scoring agree.
No hand-added score, threshold adjustment, domain match, selection or rank override.
No Builder role is attached or invented by the projection.

Apply the AST's local negative card/model path/owner token exclusions to projected
code-source candidates before admitting their new contribution. No global alias
change. Existing ordinary candidates keep ordinary behavior; the projection must
not resurrect an excluded candidate. Conflicting/unknown tails yield no projection.
The descriptor is bound to exact original query and canonical AST; do not reuse
it with another query. This is a bounded recall hint, not a downstream selection
capability. The later consumer still requires a separate reviewed source proof.
