## Nested identity first loss is an explicit producer limitation

semantic_ecma_callbacks.callback_callable_specs uses the smallest recognized named
container and forms `owner.name@line`; it does not parse an intermediate object
property path. Here indexed names are OperationPlan.execute@4 and@10, not
OperationPlan.upload.execute and OperationPlan.discard.execute. Distinct stable
keys/ranges survive; nested segment identity was never emitted. Adding nested
member/array-element identities would be a new source model, not recovery of a
serialized identity. No withdrawn nested parser was reinstated.

A newly noticed discrepancy was frozen before a follow-up raw observation: callable
primary is DiscardHandler.execute7–9, but compact anchor has DiscardHandler class

|wiki order|ID|identity|bounds|
|---|---|---|---|
|1|2|DiscardHandler class|6–10|
|2|3|UploadHandler.execute|2–4|
|3|4|DiscardHandler.execute|7–9|

query_handoff.code_anchors admits at most two records per file, so record4 is not
in raw anchors. Its exact bounds have not been replaced by record3's bounds;
record3 really owns2–4. Compact merges those two admitted records and preserves
correct record IDs and ranges. The separately computed callable evidence chooses
record4 correctly. Rebinding id3 to7–9 would manufacture identity corruption.

The existing focus guard materializes callable-primary source when it has typed,
source-operation, owner-kind/artifact or certified-portfolio permission. This
query has none of those stronger permissions; bounded status alone falls back
to the matching file anchors. The primary budget helper reserves an already
projected file, not every individual method inside it. The class6–10 already
covers the selected primary7–9, and the actual excerpt includes the whole method.
No previously promised selected-method receipt was found lost or rewritten.

A future qualified-primary retention rule would have to explicitly define why it
may replace an admitted same-file record under the existing cap, preserve graph,
log and scope obligations, and test missing/legacy IDs, ambiguous owners, overlap
and unknown syntax. It is a new retention permission, not the proposed narrow
mapping correction. Current observation does not establish missing source content
or justify a ranking change. Stop this implementation path rather than silently
expanding limits or deleting competitors.
