This supersedes the initial **adapter shortcut** stop in README.md, not its
observations. The initial review incorrectly treated unknown retention as an

## Mechanism and limits

The finite affirmative English OR request authorizes the union of two positive
source predicates: direct Stack UI construction and direct backgroundColor styling.
Observation words never select owner identity. AND, negation, quotation and extra
requests do not obtain this permission. The implementation does not fit original
owner/file/literal names or change the original query.

A new bounded Stack parser reuses the old complete component/build skeleton and
supports a finite onTouch arrow callback with zero/one simple optionally typed
parameter and up to eight this.method() statements. It proves only the direct
unshadowed Stack constructor outside callback bodies. It makes no claim about
callback/callee behavior, overlap cause or runtime execution. Unsupported syntax,
imports/shadows, dynamic expressions and other source forms remain unknown.
Arrow lexing is opt-in for the new parser; old cleanup/background permissions are
unchanged. Line terminators before arrow, special splitlines separators and strict
callback binding names are guarded. New OR owner binding names are guarded too;
reserved-looking property names are not misclassified as declaration bindings.

An early candidate passed original09 but failed independent pure Stack controls:
method_body_fts requires two terms, so a single Stack marker was not enough.
It was saved as WIP and not accepted. The final candidate reuses the existing
behavior_method_fts OR lane only for valid query-bound, explicit opt-in visual
RenderRecall. Both recall and collection use one projection function. This changes
**trial recall and scoring inputs**, not the existing weights, method two-term
threshold, ranking formula, token budgets or caps. It is not a global alias.
Source markers only identify an inspection pool; positive current-source witnesses
remain the final authority. Default/custom-port/copied/query-mismatched requests
retain old terms. Old background and cleanup requests gain no new permission.

All certified positives in the bounded pool are retained, or the whole candidate
falls back if complete snapshots cannot fit. Existing 12-path, 3-receipt, 1500-token,
digest/generation/owner/method/span, graph/path/log/identity, mutation/copy and
same-read safeguards remain. Unknowns can be skipped without an absence claim.
This is not an exhaustive repository owner search.

## Independent review and failures retained

The independent reviewer approved the corrected positive-set design and the
restricted use of the existing OR lane, then inspected the final implementation
and read the 15/15 public results. No blocking source-range/authority issue was
found. The reviewer did not independently rerun the reported unit tests.

The coordinator supplied real lexical counterexamples. Frozen before tests had
27 failing subcases in three methods: arrow line terminators, extra line separators
and strict callback parameter names. They now pass; old background behavior was
not silently changed. Initial test-command import failure and independent harness
syntax/exclusive-range mistakes remain in evidence. The latter incorrectly failed
whole-file excerpts containing complete build; it was corrected before any
production edits, with old output retained. No original evaluator was changed.

Historical README.md/REVIEW.md describe the earlier stop, not final acceptance.
The new evidence and commits explicitly correct the overly strong unknown oracle
rather than rewriting it. Remaining limitations are bounded syntax and candidate
coverage, not claims of runtime or universal visual reasoning.
