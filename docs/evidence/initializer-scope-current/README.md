# Initializer feasibility and hidden same-file callable competition

Base2f04b6d (production8d03c8a plus documentation). No field/initializer schema,
range widening, nested-member resolver or label/callback ownership contract added.

## Read-only initializer controls

Instance command array: public title/execute query already includes the sibling
label in its context excerpt; SQLite still has class plus callbacks, not a field
initializer entity. FIELD_RE is a type map used by call relationships, not a
promised producer of field source bounds. That is not a lost existing field row.

Named object with nested upload/discard callbacks: both real execute rows and
ranges exist but owner identity is flattened to OperationPlan. Both qualified
nested queries pick the first callback and originally report bounded certainty.
That does not establish two defect classes requiring a new initializer schema.
The missing nested member identity remains unresolved in this change.

A supplemental independent same-file pair with *declared* UploadHandler and
DiscardHandler exposes a narrower existing consumer defect: explicit qualified
queries correctly distinguish their existing owner identities; unqualified
`Locate execute implementation.` has two real different callable IDs/ranges yet
reports bounded with no displayed alternatives. f6cf916 freezes the public red.

## Minimal fix

`diverse_alternatives` intentionally limits presentation by path/owner-kind. It
must not erase competitors before the existing score-gap/owner-kind certainty
calculation. Certainty now sees all distinct prepared source candidates; display
alternatives, order, cap, scores, ranking and source windows remain unchanged.

Internal deduplication requires positive typed symbol ID plus path/symbol/full
callable range. Legacy fallback requires path/symbol/owner-name/owner-kind and a
valid resolved range; absent/invalid identity never proves two rows are the same.
Distinct typed IDs are not merged merely because ranges overlap. IDs remain
internal, not new public authority fields. Existing source-operation/typed-contract
precedence is preserved; this patch does NOT validate an illegal input containing
two source-operation certificates (the original branch still returns bounded).

## Freeze correction disclosed

The first new unit test mislabeled `second_start=2` as a duplicate, despite distinct
IDs and owner names. It was corrected to a true same-ID/owner/full-range copy with
one corresponding source range. The original distinct-ID/same-range input is kept
as a separate uncertain negative. The public ambiguity expectation and qualified
positive controls were not changed. The initial test fixture was NOT wholly
unchanged, and this correction is not presented as a production bug fix.
