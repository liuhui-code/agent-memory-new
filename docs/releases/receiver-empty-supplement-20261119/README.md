This release adds a bounded positive source-reading capability, not an original08
fix. A finite complete affirmative request, originally empty raw code anchors and
no primary/alternative callable evidence may receive all one or two independently
validated direct receiver-update callback methods. Existing results never enter
this supplement. There are no new index labels, shared-ranking changes, default
budget changes, or inherited collectionfold/record-loop selection authority.

## Bounds and evidence meaning

Enumeration is complete within at most12 files,256 symbols and128 callable rows,
using LIMIT upper-bound+1, a consistent SQLite snapshot and active generation.
Source reads are capped at256KiB/file and1MiB total. A shared0.5s qualification
budget is checked across source work; each SQL inventory has a0.2s progress check.
These are fail-closed resource controls, not a guaranteed hard OS I/O deadline.
Whole limited methods, lexical receiver/item binding, owner identity, ranges,
generation and source hashes are checked. Database and source are checked again
before selection. Additional source_snapshot metadata explicitly binds generation
and digest. The outer freshness report continues to describe original recall.

The syntax only proves `this.field += item.member` appears directly in the specified
arrow callback. It does not prove numeric types, native/synchronous forEach,
execution, quarter-selection linkage, causal diagnosis or a unique business owner.
Unknown syntax abstains. Non-source evidence is retained. A raw control explicitly
preserves five logs and one fact, and recomputes raw coverage rather than copying
compact counts. Old callable alternatives prevent takeover.
