# Default compact additive method display

Follow-up to c1892017. The same authenticated, transactional method-envelope capability now runs for default compact output too, after existing reading-order decisions. It adds source only if the unchanged current budget permits; no summary, advice, candidate, score, log, graph or other excerpt is deleted or reordered. Raw remains outside the hook. No compact array representation, new estimator or lossy budget trade was introduced.

Existing file-record anchors can legitimately project a selected method rather than the containing owner. The guard now accepts that representation ONLY when file record ID matches and projected symbol, source_ranges and read_window all equal the unique authenticated method's full identity/bounds. Current digest/generation, owner, method kind and exact prior excerpt bytes remain mandatory. Wrong projected bounds decline.
