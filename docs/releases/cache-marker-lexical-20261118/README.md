# Cache marker lexical purity (Development, 2026-11-18)

## Before production edit
Frozen independent protocol has a real PruneEngine scan and ReferenceText / TemplateText methods returning only examples. Normal public init/learn/context incorrectly indexed literal-only ReferenceText as cacheeviction and returned it alongside PruneEngine for the frozen executable-scan request. This is a source-backed producer defect, not a timestamp-source certificate or an original33 completion.

## Limited change and results
Only the four existing cacheeviction predicates now inspect a successful callback_mask_lines lexical mask. Ordinary quoted strings, comments and plain templates cannot supply operations. Unknown lexical input (including regex, interpolation and unclosed text) keeps the legacy source; no claim of absence is made. Other markers, query recognition, ranking, graph storage, schema and budgets are unchanged. No TypeScript marker expansion.

Final public scan anchors contain only PruneEngine.prune. The explicit ReferenceText.example request preserves exactly the same two anchors as before. Existing snapshots are not magically updated: normal learn-path on a copy of the original seed refreshes the summary and reproduces the final scan output. This does not prove receiver/field binding, real runtime eviction, LRU policy or the original33 target choice. A quoted property name can no longer itself supply the lexical age token; the hint remains conservative/non-exhaustive.

80 focused tests passed, including cache source/selection/public contracts, behavior hints and disclosure lexical/scope tests. Python 500-line check passed. No full gate or original-case aggregate rerun.

## Retained rejected candidate
The initial candidate used code_mask directly and its public outputs are retained as after-*. That candidate was not published. Independent review identified regex quote and executing interpolation ambiguity; final-* uses the conservative existing callback lexer and unknown-input fallback. The final test controls include these boundaries. Old results and frozen sources/queries were not edited to turn red green.

## Language investigation

There is no existing TS/ArkTS cacheeviction parity promise. The previous WindowCache generic Chinese no-recall observation therefore does not authorize adding these rough markers to TS. This release addresses the independently demonstrated lexical defect instead.
