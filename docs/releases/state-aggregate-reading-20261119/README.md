## Why this is not the rejected1501 experiment

The old experiment relied on plain receiver += and broader state/iteration wording;
its full proposed default envelope exceeded1500. No metadata was removed to rescue it.

all directly updated receiver fields must be declared @State number in the same
component's closed field prefix; the method must satisfy existing complete direct
forEach syntax, with no deferred callback or unknown body. Unknown prefix/decorator,
ordinary number, duplicate declarations, same-name methods and mismatched field/owner
are rejected. This still proves syntax and declaration binding, not runtime behavior.

with a distinct static_state_receiver_update reason and supporting role. Its1479

Reuse EmptyReceiverSession's single final accounting point and original authenticator.
Its old request grammar/API defaults are unchanged. Empty requests use the old bounded
complete inventory:≤12files,≤256symbols,≤128callables. Nonempty requests use only current
callable candidates with exact file/owner/name/full callable-symbol bounds, never other

are checked; all candidate files are verified. Read cap256KiB/file and1MiB aggregate;

already-authenticated receipt bytes, then inventory/source are revalidated. Empty
insertion uses the original transaction; nonempty insertion only appends source.

possibly committed writes. New source bodies remain subject to existing redaction.
