## 目标与当前证据

用户要求从设计方法讨论推进到可直接使用的交付。现有
[设计协议](../skills/agent-memory-query/references/code-design.md)已经要求目标、源码、原则、
候选和验证；本轮没有证据将它归因为 Runtime 服务缺陷，也没有证明新增架构抽象必要。
因此只补充 Agent 可操作的输入引导、参考适配审查、取舍示例、决策记录和有条件反馈。

当前已观察到的另一项缺口是 [M1 的 Rust 上下文为空](arklog-m1-design-experiment.zh-CN.md#7-memory-集成的实际缺口)。
它是独立的源码能力问题，不用本次 Skill 交付冒称修复，也不作为设计收益证明。

## 本次真实设计决定

| 输入 | 内容与依据 |
|---|---|
| 目标 | 用户要求完成上一轮收缩后的方案，交付现有 Skill 可用的设计支持 |
| 硬约束 | 四个 Skill、唯一 Runtime 入口、SQLite 真相源、Agent 负责设计判断；来自项目现行约束 |
| 非目标 | 新的模式评分服务、Rust 解析器、自动改规则、真实活动或上游发布 |
| 质量优先级 | 指导可执行且按需加载；保留证据与未知的区别；兼容现有查询和反思 |
| 未知 | 是否改善新任务设计、额外上下文成本、Memory 相对更好的 Skill 的独立收益 |

参考选择：ADD 用于识别驱动因素与机制选择，arc42 用于输入缺口；Ousterhout / Google
用于复杂度与评审问题；DPR / MADR 用于材料和决策结构。EIP 仅为集成问题的领域参考，
不据此增加消息系统。原始来源与适用限制见
[随 Skill 安装的参考指南](../skills/agent-memory-query/references/design-reference-guide.md)。

| 候选 | 取舍与决定 |
|---|---|
| 扩充 Runtime 自动匹配、排名与选型 | 当前无共同契约缺陷证据，且违反现有 Agent/Runtime 职责；不采用 |
| 在已有 Skill 内加入按需材料和具体审查问题 | 复用现有安装与接口，能形成实际交付；采用，设计效能保留未知 |
| 只补一份参考书目 | 不能体现任务输入、失配审查和实际取舍，不能完整回应用户要求；不采用 |

接受的代价：更多指导文本有上下文成本，且不保证 Agent 每次遵循。因此主入口仍是轻量路由，
模板与示例按需展开；局部修改无需完整架构文档，不强制候选数量。若后续发现指导没有改变决定、
只使产物变长，应缩减或撤回对应指导，不以扩大模式数量补救。

## 已实现的使用路径

1. 用户自然语言提出任务，沿用原 Skill 路由与 `design-context` 两轮上下文。
2. Agent 从任务和已审阅项目资料预填设计简报，标明需求、事实、假设和未知。
3. 按问题特征读取参考，核对前提、失配和可迁移范围；找不到适配参考也是有效结果。
4. 对实质不同的机制比较责任、状态、失败、调用方负担和可信变化，不用机械总分。
5. 重要决定可使用 [决策模板](../skills/agent-memory-query/references/design-decision-template.md)，普通任务不强制写 ADR。
6. 实际尝试后经原 Reflect / experience-usage 记录有条件的经验和复用反馈。

[工作示例](../skills/agent-memory-query/references/design-examples.md)明确区分一个历史开发案例
和两个编写的说明案例。示例不是独立 Agent 的运行结果，也不是新的 holdout。

可以直接向已安装此版本 Skill 的 Agent 提出：

> 结合当前项目设计这项改动。先补齐会影响取舍的输入，核对相关项目决定；
> 对真正有差异的方案说明收益、代价和参考失配条件，按当前授权继续完成。

## 重审与后续效能验证

若指导失配，先查明是输入遗漏、原文误读、历史迁移错误还是模型判断问题，再定向修正。
若以后要比较收益，应分别观察当前方式、改进 Skill、同一 Skill 加 Memory，固定共同条件，
明确独立评审与停止规则，并统计失败、返工和总成本。现有 diagnosis Cohort 不自动获得
设计任务资格；按原 [变更政策](evaluation-and-change-policy.md)另行建立适用合同。
