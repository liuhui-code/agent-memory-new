# P2：设计指导与项目 Memory 的对照准备

日期：2026-11-18。状态：开发准备；真实活动未启动，运行合同尚未冻结。
本文件是后续设计任务的评测工作约定，不是新增 Runtime 协议或已经批准的活动。

## 要回答的问题

[P1](design-preview-development-case.zh-CN.md)证明当前 Agent 能按指导走通一个受控案例，
没有证明指导提高设计质量，也没有证明项目 Memory 的增量收益。本阶段把问题拆开：

- 新指导是否使 Agent 更早发现决定性约束，减少错误边界和实际返工，代价是否值得？
- 在相同指导和源码能力下，已有项目经验是否改变了有依据的决定或避免了重复错误？
- 哪些任务不需要这些材料；遇到不适用经验时，Agent 是否会拒绝迁移？

输入整理、原则引用、模式命中和文档长度都只能描述过程。设计好坏要看当前行为、责任边界、
失败路径、调用方负担，以及一次可信变化的实际传播；不合成“品味总分”。

## 三组处理与共同条件

| 组 | 指导 | 查询可见资料 | 能回答什么 |
|---|---|---|---|
| A：现有 Skill 基线 | Git `320e951` 中的四个 Skill，20 个资源 | 当前源码索引、共同项目契约、共同通用目录；无额外 Runtime 项目历史 | 现有指导的表现；不是裸 Agent |
| B：改进指导 | P0 冻结的四个 Skill，23 个资源 | 与 A 相同，无额外 Runtime 项目历史 | B−A：本轮指导包的作用 |
| C：改进指导加历史 | 与 B 逐字节相同 | 在 B 的相同底座上增加任务开始前已存在的项目历史 | C−B：项目历史包的增量作用 |

三组使用同一 P0 Runtime。A 也得到 Rust 支持和当前源码导航，不能把新解析器算成指导收益。
基线 Skill 来自实际 Git 对象，不是人为删去原则的弱提示词；差异限于 Query 主入口、
`code-design.md`、Reflect 主入口的修改及三个新参考资源。
精确文件和摘要见 [arm-manifest.json](evidence/design-comparison-preparation-20261118/arm-manifest.json)。

这里的 Memory 处理特指额外的项目历史。共同当前契约、源码索引、通用设计目录以及索引过程
自动生成的学习记录不属于处理差异。这些设置记录保留在三组共享底座中，不要求 A/B 的数据库
绝对零记录，也不删记录凑出“无 Memory”标签。
B/C 的 Skill 自带 M1 工作示例，这是指导包的一部分；不能把 B 称为从未见过历史知识。
因此 B−A 比较的是整个指导包，不能进一步分离原则、示例或参考指南各自的作用；
C−B 比较额外 Runtime 历史档案，不能扩大解释为整个 Memory 产品的收益。
项目经验若已公开在共同 Git 文档中，三组都能读；这衡量历史的检索/复用价值，不能声称 C
独占该知识。若 C 改变了约束、源码、模型或调查规则，配对失效，不能归因于 Memory。
如以后要测裸 Agent 或整个 Memory 产品，需要另立比较，不能改写本次 A 的含义。

首次执行前必须冻结以下共同条件：

1. 原始任务摘要、同一源码 revision/tree 与全部未跟踪材料的显式清单。脏任务只能自然观察，
   不能凭 Git HEAD 相同宣称配对。当前未提交开发快照本身不是合格真实任务。
2. 同一模型/版本、参数、工具权限、环境、任务提示、预算、调查规则和验收。不只给 C
   注入更好的指令。通用参考的访问策略一致；B/C 新指导本身的阅读计入处理成本。
3. A/B 的无历史底座与 C 的任务前快照；相同源码、规范、目录逐项匹配。C 增量含哪些
   semantic/episode/reflection 等记录必须列清，私密内容在受控资料保管处，不抄入 Git。
4. 不带其他组会话、全局历史或隐含 Skill 的隔离宿主。每组从相同工作区起点独立执行，
   不接触另一组方案；顺序/重复次数/重试政策提前固定。复制三套文件不证明宿主已经隔离。
5. 查询、参考阅读、提示构建、模型工作、验证、返工的总预算和停止条件。模型不确定性仍存在，
   相同参数不保证相同输出；不得运行到出现喜欢的答案再挑选。

只读证据快照与执行目录分开。Runtime 查询可能写派生结果/使用轨迹，因此每组使用自有可写副本，
不能把实际执行的 Memory Home 描述为物理只读。所有试验反馈先隔离，不回流其他组或后续任务；
若要研究在线学习，需要单独冻结更新政策。

## 任务来源与入组

真实来源、连续性负责人和开始时间尚未指定。未来采用固定 presented 数量的连续队列，
每个到达任务保留序号，排除项也占名额；数量、排除原因、配对容量及停止条件在首个任务前冻结。
不能将“有设计空间”“Memory 机会”在看到好答案后才补写。任务开始时分别标记：

- 是否存在实质的责任、接口、状态或质量取舍；局部改字无需强制候选和模板。
- 是否具备配对条件；不满足的任务仍记录来源和原因，不能悄悄换成更好做的任务。
- 历史机会 present/absent/unknown：present 必须引用任务前已有记录及其可能相关的条件；
  这不是相关性已成立。全体任务、设计子集与机会子集分账，不用机会收益替代日常收益。

M1、P1、已阅读的失败和本阶段合成资料全部属于已知开发材料，不能重新包装成隐藏任务。
没有来源时不生成“真实队列”，不补造未来需求，不用任务数量装饰完成度。
原始任务、工作产物和受控运行记录由指定保管人留在 SQLite 外；Git/Runtime 只收适当的摘要、
类型化引用与有界统计，不保存私密任务、查询正文、日志或模型推理。

## 怎样评审设计

采用 [任务与评审工作表](eval/design-comparison-task-and-review.template.md)。
任务说明/客观验收由任务负责人在执行前固定；评审人不为某个模式预写唯一正确架构。
设计作者不能兼作独立评审人。当前 Agent 的 P1 校准属于自审，不计独立一致性。
评审尽量隐藏组名和呈现顺序，但文风可能暴露处理，实际盲法限制需记录。

先核对相同任务和硬约束，再比较有证据的取舍：

| 维度 | 可判断的好坏对照 | 需要的证据 |
|---|---|---|
| 输入与未知 | 先查明线程模型，或将未知保留为条件；相反，假设串行后直接套单所有者 | 初始问题、源码锚点、决定前记录 |
| 边界与状态 | 完成身份与发布同一受控提交，耗时渲染在外；相反，多处分散校验或渲染持锁 | 当前行为反例、源码和执行结果 |
| 抽象与复杂度 | 两种真实格式共享小函数契约；相反，只换个名字就增加注册表/生命周期层 | 调用路径、选择责任、错误处理和读者负担 |
| 演进与取舍 | 预先指定的格式变化局部完成且保留行为；相反，行数少但更改传播到多个调用方 | 变化需求先后顺序、实际补丁和回归 |
| 参考适配 | 提取“提交时核对身份”，拒绝复制串行和 Stop 语义；相反，引用正确书名却用错前提 | 参考原文、匹配/失配说明、决定变化 |

表中用 P1 举例帮助理解，不规定所有新任务都用锁、函数或同一边界。
高质量候选可能采用队列、类或现有平台机制，只要适用前提和总代价支持。
测试通过先说明声明行为；架构质量仍须结合任务审查。代码行数/文件数可辅助说明影响面，
不能单独判优。可信变化必须由任务负责人提前给出依据，不以“恰好适合本实现”倒推。

每个任务分别保留硬约束结果和定性比较：better / tie / tradeoff / inconclusive / invalid。
有冲突时写明谁承担代价、哪项优先级决定取舍；没有足够证据就不强行选胜者。
两个可行方案不因不同于作者偏好就判错；异议与复核保持可见，不投票制造 Oracle。
不允许用清晰文档抵消行为失败，也不允许用一次测试通过抹掉不可信的并发/数据假设。

## 结果与成本分账

| 记录 | 解释限制 |
|---|---|
| 任务验收及失败/返工 | 相同客观检查、修正轮次和未解决问题；只讨论当前任务 |
| 边界/抽象/变化评审 | 指出具体补丁、调用方影响、已接受代价；不能合成总分 |
| 历史使用链 | 记录任务前经验引用、可见采用/拒绝、决定前后差异；Agent 自报“有帮助”不是因果证据 |
| 端到端成本 | 从分组请求接收至结果读取完成，包含查询、工具、阅读、验证和返工；Token 未知保持 unknown |
| 准备成本 | 索引、历史整理/维护和安装另记；任务内新增学习/维护计入该任务，不隐藏或任意摊销 |
| 比较有效性 | 同源、同模型、隔离、预算、完整事件、所有失败和退出；无效配对另报，仍占已到达任务名额 |

最终分别报告 B−A 与 C−B，保留逐任务依据和所有 ties/负例。小规模只作 Development 描述；
不宣称显著性、泛化、自动晋级或长期递归效能。若 B 只让文档更长、没有可信决定或返工改善，
应缩减指导；若 C 没有额外帮助或导致错误迁移，应收缩相应复用条件，不扩充模式库解释失败。
不因个别成功跳过成本上限；可接受成本界限和汇总判断规则必须事先写入活动工作表。

## 停止与当前就绪状态

有以下情况停止相应比较并保留记录：任务/源码漂移、跨组泄漏、Memory 晚补、事件或成本缺失、
预算耗尽、无法辨明失败层，或验收/原则在看到结果后改变。基础设施错误只按事先约定的重试
政策处理；修复后不得覆盖首次结果，也不追加有利任务弥补失败。不能认证连续性时如实标记。

当前状态由 [readiness.json](evidence/design-comparison-preparation-20261118/readiness.json)记录：

- internal：三组开发字节材料和资料差异可固定；设计任务没有现成的已接通活动合同。
- external：真实项目/来源、任务前 Memory、负责人、保管与独立评审尚缺。
- campaign：presented 数、模型、预算、配对和停止配置未冻结，保持 `no_go`。
- evidence：只有隔离资料/接口演练和 P1 自审；真实任务、模型运行和独立评审数量均为零。

现有 `prospective-agent-cohort/v1` 与 `agent-benchmark-treatment/v3` 仍限定 diagnosis。
本文件和工作表不能传给 `eval-cohort-create`，不能通过换 task_type 绕过
[R4 就绪门禁](system-meta-reflection-campaign-readiness.zh-CN.md)。真实活动启动前须另行
审查适用设计合同、隔离/成本记账的宿主执行能力及用户对该活动的授权；本次不实现通用评测器。

## 本轮交付与下一步

本轮固定 A 的原始 Skill 包与 B/C 的 P0 摘要，使用合成源码和一条明确标注的合成历史，
通过实际安装及公开 `learn-path` / `reflect` / `design-context` 接口核对资料差异。

保留首次计划、脚本与结果，修正开发检查的预期为共享 episode 加 C 的增量，未修改 Runtime。
