# Offline name-association result review

Read experiment.py (implementation f830c1d), protocol/results/summary in
listener-model-v2/docs/evidence/listener-request-association without rerunning.
Frozen 35 controls have 35 expected status matches. Six saved original query
observations have pass:null, not six additional passes. No public ranking result
or repaired original variant is demonstrated.

Exact case comparison precedes weak CamelCase/acronym/underscore segment matching.
The segment lane uses no stopword removal or on-prefix exception; it can therefore
associate failure with onFailure, failureCount or retryFailure separately, and
reports collision when several such distinct spellings are present. That is a
name observation, not a callback-semantic equivalence rule. Exact-priority chooses
exact spelling even when weak spellings exist; this is an explicitly frozen lane
policy, not evidence that other functions are irrelevant.

The target-member lane is separate from dual-name hypothesis. The mismatch control
retains accepted→rejected in the former and finds no association in the latter.
The latter explicitly marks property_selector_assumed=true; neither lane establishes
that the user required matching callback property and invoked member names.
Two forwarders retain multiple observed identities. Partial domains may still
report exact-name:one-observed while coverage=partial; all outputs deny global
uniqueness, relation satisfaction and ranking eligibility. Do not drop coverage
when presenting or consuming the status. Empty capped/old-index domains are unknown.

All recognized descriptors retain source/target-prefix qualifiers as unverified,
and relation_attachment_unresolved=true. Actual saved independent generic gives
exact-name association; native failure gives segment-uncertain association. The
four other saved queries are unsupported by this narrow grammar. None is a new
success or regression in the public runtime, because this experiment is not used
by that runtime.

## Concrete remaining consumer obligations

1. The grammar demonstrates a bounded observational descriptor, not verified NL
   semantics. ASCII source/qualifier spans and an exclusion-word set do not prove
   all negation/extra-request/wrapper variants rejected. Do not promote it to a
   general intent authority using these 35 examples alone.
2. Unverified source qualifiers (engine/native runtime/host etc.) cannot disappear
   if future retrieval claims request satisfaction. Preserve them and existing
   candidates, or validate a specifically defined source relation independently.
3. A consumer may expose exact/weak associations for inspection without exclusive
   pruning. Any ranking/primary/anchor authority is a separate proposed contract,
   with fixed public before/after, actual body and false-positive controls; the
   present flags explicitly prohibit that authority. Do not infer a stronger
   permission merely because the isolated descriptor found one match.
4. The input facts here are frozen reduced records, not the fully integrated,
   validated runtime side payload. Production would require version/snapshot/typed
   identity checks and explicit coverage/truncation propagation, including duplicate
   identity policy. Same identity appearing in more than one record is set-deduped
   here; that is not a production conflict-resolution guarantee.
5. Natural segment association remains uncertain even without an observed collision.
   A partial supplied domain cannot certify absence of other spellings. Exact
   matching is a useful narrower candidate, but still does not prove callback
   property attachment, SDK registration, causality or unique source ownership.

Verdict: accepted as a correctly bounded offline observation stage. A concrete
next consumer experiment should choose a nonexclusive evidence-display contract
or explicitly specify and independently test a stronger selection permission;
these are not interchangeable. Preserve original generic red while designing
that step. No change to current production, model integration or original oracle
is approved by this report, and the broader project is not declared blocked.
