# V2 isolated model experiment: review contract before new execution

This is a new experiment stage, not a ban on revising the rejected overlay. Keep
old 20-source and five-query inputs/oracles plus the old 19/20 result intact.
No production consumer, request parser or score change is authorized here.

## Responsibility split

Source-time producer validates known lexical input, complete supported body shape,
exact case-sensitive receiver/member tokens, formal binding and inner containment.
It binds evidence to existing symbol identity/signature/ranges and source digest.
Decoder validates version, exact structure/types, formal identity against signature,
consistent source identity and snapshot digest, declared coordinate unit and legal
nested bounds. Without source bytes it cannot re-prove lexical/body facts; those
remain assertions of the already trusted provider. State that trust boundary.
Optional source-time revalidation may provide a stronger boundary, but do not
require a source-free decoder to prove arbitrary program semantics.

## Record and budget obligation

Do not join on lowercase descriptive detail as a callee identifier. Preserve exact
source tokens/ranges in the typed fact. Attach to a source identity directly; if an
existing mechanism association is required, establish it from extraction provenance,
not a normalized display string. Same-line/case-colliding calls must not select an
arbitrary record. Unknown association may omit the new evidence, never rewrite
legacy metadata or certify absence.

Baseline legacy mechanism list, order, encoded payload and derived search terms
must survive identically. Applying the old 4096-byte packing only after enlarging
records is insufficient. First pack unchanged old records using the existing cap.
A new optional evidence transport needs a separately explicit bounded allowance
or can be omitted when it cannot fit; neither route silently raises an existing
budget or evicts old facts. Any new persistence field/allowance is part of the model
proposal, not “free metadata”. Facts must be complete, never partially truncated.

Version dispatch must explicitly handle old v1 with new-field contamination:
reject the incompatible combination, or drop it as unknown with documented behavior.
Do not relabel old input and authenticate the field. New-version and nested unknown
fields need a specified strict/forward-compatible policy, not accidental acceptance.

## Minimum new pre-frozen controls

1. Native exact onReady/onFailure produces both source-bound facts; case-distinct
   members onFailure/onfailure must remain distinct, including same-line ambiguity.
2. Old v1 without field remains accepted; old v1 carrying the new field follows
   frozen reject/drop behavior. Unknown version, wrong nested type, unknown unit,
   bool coordinates, extra nested fields follow the declared validator contract.
3. Formal index changed to another valid slot, name/type inconsistent with signature,
   mismatched key/path/range/digest and invocation receiver are rejected. A source
   validator test and decoder test are separately labelled, not conflated.
4. Near-4096 baseline legacy payload, first oversized new fact and multiple facts:
   old bytes/order/search terms unchanged; new evidence either complete or absent.
   Verify actual public indexed output, not only a standalone serializer.
5. Serialization roundtrip, code-only installation and ordinary merge on same bytes;
   old reader behavior explicitly tested. Missing records remain unknown.
6. The old 20 source controls and five query protections remain unchanged. Generic
   red stays a red unless an independently approved consumer fixes it; no producer
   or schema green counts as selection improvement.

This remains potentially a local optional adapter/model increment if limited to
these source facts and existing evidence transport. A generic scope/def-use graph,
SDK registration resolver or exclusive selection authority would exceed it. Adding
a formal optional field is still a real versioned model change requiring review.
These are proposed acceptance obligations; no v2 outputs are claimed yet.
