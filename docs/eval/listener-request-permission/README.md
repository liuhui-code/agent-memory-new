# Listener request/model permission review

Base d4a4906. Read AGENTS, evaluation policy, retained listener design/public red,
typed-parameter-invocation protocol/README and weak-typed-reservation evidence.
Only a frozen offline request/token experiment was executed once. No public
context, full evaluation, production/schema/weight or original-source edit.

## Concrete request experiment

Eight fixed cases in protocol.json precede probe execution. Existing classifier
outputs matched all eight expected descriptors. Both actual bind-contract requests
return None. Explicit parameter invocation returns the existing parameter relation;
literal returns literal; negative/multiple/wrapper do not gain a binding relation.
These are observations, not a new classifier accepting those generic requests.

Surprising but retained: identifier_tokens('rejected') returns [], whereas
identifier_tokens('onFailure') returns ['on','failure']. Thus this splitter cannot
be the sole member-identity parser even for the independent exact rejected name.
The same failure token matches failureCount and retryFailure. A token match is
not a unique or exact member selector, nor proof the words request a callback
property rather than invoked member. No on-prefix stripping or case-specific
synonym was introduced to recover the native failure request. `safe_token_authority`
is a frozen design boundary, not a tested implementation's boolean output.

Executable decision: do not deploy a binding consumer using this tokenizer.
Exact case-preserving identifier comparison could be one ingredient of a future
explicit descriptor, but the original native failure/onFailure request still
requires separately justified member-reference semantics. An explicit descriptor
must distinguish requested type spelling, callback property, invoked member and
relation kind, preserve text/wrapper/negative/multiple scopes, and stay unknown
when attachment or any selector is unresolved. It cannot rewrite binds to accepts.
This review implements no replacement request grammar.

## Is there a second independent defect?

Saved typed-parameter-invocation/before.json actually gives Direct and CommentOnly
weak typed matches with uncertain certainty; OtherReceiver/DifferentParameter have
no typed flag and ordinary fallback may still be bounded. The initial protocol
expected no typed flag on CommentOnly. However, its README explicitly corrects
the initial assumption that this flag promised strong receiver identity. Existing
weak API behavior is not a broken strong evidence contract.

That does not make the task irrelevant: a user asking for invocation on a parameter
has reason to prefer Direct over a documentation-only mention. It motivates an
additional reliable source fact. But the subsequent frozen samefile/reservation
oracle required Direct's actual range retention, now repaired. It did not require
Direct to be primary. Primary=CommentOnly cannot retrospectively be relabeled a
second frozen strict-primary failure. No new oracle or public run was made here.

The two subjects share a plausible receiver-binding subfact. Callback forwarding
also needs real argument/object/property-arrow containment and captured-binding
scope. These are different obligations, not two variants automatically proving
one complete missing contract. Current evidence supports motivation and limited
producer feasibility, not a completed two-independent-defect architecture gate.

## Typed representation permission

An optional structured, versioned semantic payload is a real model/protocol
change even when persisted in an existing JSON column. It is not automatically a
new architecture: a local adapter fact can remain inside existing evidence
transport. Conversely a generic scope/def-use/registration graph or new exclusive
selection authority is a new abstraction; the repository's two-class requirement
cannot be bypassed by calling it metadata. No such architecture is approved here.

The bounded 20-source offline shape feasibility permits proposing a local model
increment, not silently installing it. Before approval specify exact optional
field/version, strict decoding (unknown/malformed versions are not evidence),
source-key/digest/outer-signature and inner-interval joins, duplicate identity and
cap atomicity, serialization roundtrip and legacy compatibility, ordinary relearn
activation, actual public learn/list acceptance, and no authority from missing
facts. Keep declared type spelling distinct from resolved external type identity.
Full callbacks outside the narrow whole-body grammar remain unknown. Do not hide
proof in descriptive detail strings or upgrade legacy weak typed matches.

Next actionable bounded step is a reviewed model-only proposal with those explicit
validation/public persistence controls and no consumer. That proposal may be judged
as a local adapter extension; if it requires a general binding resolver, stop for
architecture evidence instead. Original native query remains historical 2/3 and
its independent generic binding red remains unresolved. No repair gain claimed.
