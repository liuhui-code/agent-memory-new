## Recommended next investment: Builder request consumption (23)

The published `arkts_builder` producer already supplies the positive declaration
fact; rebuilding it or another parser extension is not the next task. Its fixed
public competition remains one red and four protected controls. See
[producer reconstruction](../evidence/builder-role-rebuild/README.md) and
[source/request boundary](builder-source-role-review/README.md).

The smallest useful design is a request-to-existing-role contract, not a new graph:
when the request actually seeks a declared Builder, use the authenticated role
without renaming component ownership or declaring unknown methods non-Builders.
Before a consumer edit, freeze complete request recognition and protection for
instructional/literal text, generated source, wrappers invoking Builders, ordinary
components, explicit other identities, multiple Builders and unknown syntax.
Keep the existing public input and oracle unchanged. A role word alone is not
authorization; a narrower rule that never covers the original red is not a repair.

**Tradeoff:** this has the best established source facts and smallest new consumer
surface among the reviewed options. Its hard part is language attribution, not
metadata. A successful gate still does not promise original-case precision. Stop
if it needs fixture-specific words or erases legitimate multiple/literal requests.
This is a recommendation for a reviewed design, not acceptance of a new rule.
