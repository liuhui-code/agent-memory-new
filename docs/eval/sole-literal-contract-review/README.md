# Sole literal return: independent negative-fact review

Read-only review at base `14d714f`. No new query, fixture, test, runtime edit or
oracle change. Historical evidence is not a fresh current-baseline measurement.

## Two actual evidence families, with stage distinctions

`before.json`, `after.json`, `frozen-tests.py.txt`, `rejected-hint.patch`.

and CacheMonitor.render are protected positives. The rejected marker candidate

The earliest output baseline loses collect at diversity/budget admission, before

SingleRead and the description class. Callable primary is OutputDescription.label
at 29.0, certainty bounded, with summary/string evidence reasons. Compact retains
only OutputDescription. This later observation matches the cache competition
boundary. It is not an invented salience trace: no claim is made that the output
competitors were admitted by the same salience function as another family.

The output fixed generic oracle forbids both OutputDescription and SingleRead and
requires collect. Its explicit controls historically also fail specific-symbol
checks because class/file projections are returned. Those old failures remain
failures; do not call all explicit controls green or weaken their expectations.

## What this does and does not justify

Unlike the attempted cache/shared-record unification, these are two independently
frozen operation domains with a matching late competition observation: a concrete
literal-return callable beats already recalled executable source. They support
investigating ONE narrow source fact: the complete supported method body consists
of a sole direct return of a literal. That fact does not need an LRU, full loop
algorithm or cross-method dataflow proof. Current cache requests do not ask for
access-recency/LRU correctness or guaranteed final capacity.

This is evidence for a bounded feasibility study, not automatic approval of a
new architecture, producer schema or serving policy. The source fact alone says
nothing about the user's requested target, relevance of a wrapper caller, the
absence of other algorithms, or the correctness of a competing implementation.
In particular, excluding a label could still choose SingleRead and fail output's
unchanged accumulation oracle. Cache FIFO must remain real/unknown, not absent.
Two domains are not proof that a proposed primary-selection consumer is safe.

## Minimum source-fact boundary

A future proof must be tied to the actual indexed method identity, exact body
bounds and same bytes/digest; string_evidence or method labels are insufficient.
Only a completely understood body with one direct literal-return statement may
qualify. Missing/incomplete/truncated source, unknown syntax, mixed statements,
interpolation, calls, getters, coercions, computed expressions, nested scopes,
conditional returns and aliases must not acquire this fact. Multiline strings,
escapes, return/newline automatic semicolon behavior, braces in comments and
literal contents need explicit grammar treatment, not a greedy source regex.

The fact should be named for syntax, not semantic irrelevance. If only the body
is proven, do not describe the entire invocation as side-effect-free: default
parameter expressions, decorators or other surrounding execution are separate.
Do not infer body absence from an excerpt omitting its statements. Legacy indexes
and unrecognized adapters stay unknown until actual ordinary relearn produces a
compatible record. JSON copies cannot manufacture source-reading permission.

## Consumer constraints and falsifiable controls

Before serving, define reviewed request binding to an executable-operation target.
Do not delete literal words from queries or globally demote string-return methods.
Explicit names, requested literal/text/description/configuration, actual logs and
multiple targets must preserve their existing rights. A constant-return method
can be the correct implementation of a requested label or response function.
Mixed methods that log or call before returning a constant are not sole literal.
A real wrapper calling a helper is not literal-only, nor are indirect operations.
Unknown syntax/metadata, real FIFO, SingleRead and second real operation owners
cannot be assigned absence merely because they lack a supported positive witness.

Controls still needed before approval (not created/run here): explicit label and
literal requests, true logging and mixed log/return bodies, pure literals beside
same-file real methods, wrapper/indirect implementations, a literal-return target
whose value is the requested behavior, malformed/stale/forged identity, old-index
activation, multiple and unknown competitors, budget displacement and full actual
required body coverage under unchanged caps. The exact old public oracles remain
required; keeping source while choosing the wrong primary is not completion.

## Existing certificate must not be repurposed

`query_source_operation.certify_source_operation` currently supports only
runtimecapability/persistenceread. It has typed/exact identity, multi-target,
unknown adapter/role and source identity vetoes, then certifies one positive
operation candidate within the recalled set. A sole-literal fact is negative
syntax about one method, not a positive operation proof for any other candidate.
Do not add cache/output to its supported set, set source_operation_match, use
source_operation_checked as a new absence certificate, or waive unknown/explicit
vetoes to make the new proposal pass. Separate source fact and request-conditioned
consumer permission. No such implementation is approved by this review.
