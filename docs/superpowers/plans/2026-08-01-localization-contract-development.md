# Localization Contract Development Plan

## Objective

Reproduce the next localization failures in independent, project-neutral ArkTS
fixtures and in the public compact `query_handoff`. Identify the first proven serving
failure before changing extraction, retrieval, ranking, range selection, or compact
projection.

No consumed holdout source, case, result, query, threshold, or Oracle may be read,
modified, or rerun during this stage.

## Evidence Classes

The development portfolio contains five controlled cases:

1. an inline `@Builder` callable that owns component retention;
2. an inline `@Styles` callable that owns conditional visual state;
3. a recognized method in a dense coordinator where only method-body evidence explains
   the task;
4. a Chinese task description for an English cache-key implementation;
5. one correct settings transition owner among several same-domain sheet owners.

The first two are independent behavior classes that exercise one syntax contract. The
third separates callable ranking from extraction. The fourth separates file recall
from callable localization. The fifth separates retrieval from compact projection.

## Execution Order

1. Add only fixture source and a classified editable development case pack.
2. Execute the existing capability evaluator to record the pre-change public-output
   baseline.
3. Inspect candidate file, localizer file, callable, range, evidence primary, compact
   primary, and compact anchor stages for every failure.
4. Add focused red tests only for failures proven in `query_handoff`.
5. Reuse `HierarchicalLocalizerPort`, normalized callable headers, typed file-candidate
   fusion, and compact evidence contracts where they already express the requirement.
6. Change architecture only if at least two independent defect classes prove the same
   missing contract; otherwise make at most a bounded implementation correction or stop.
7. Rerun the development pack, then the complete development capability gate and
   performance gates. Reject any previous pass-to-fail regression.

## Acceptance

- Every accepted service change has a red/green public `query_handoff` regression.
- No project name, source path, case phrase, language-specific business noun, Oracle,
  or holdout-derived threshold appears in production behavior.
- Candidate and output budgets remain bounded.
- Runtime returns evidence only; the Agent retains diagnosis responsibility.
- Python compilation, JSON, diff, exactly four Skills, and the 500-line limit pass.

## Stop Rules

- Stop if a failure exists only in shadow audit and not in compact handoff.
- Stop if the first failing layer cannot be distinguished.
- Stop if two independent cases do not support an architecture change.
- Stop rather than tuning weights or thresholds from external evaluation evidence.

## Result

The five-case pre-change baseline passed 3/5. Dense method-body ranking and same-domain
compact projection already passed and were removed from the repair scope. Inline
`@Builder` failed the formal source-span check, while inline `@Styles` exposed the same
missing callable/range only in shadow audit. The Chinese cache-key case failed first at
candidate-file retrieval.

Focused red tests proved that the public compact handoff attached the component source
window to `build`, not the decorated builder callable. The existing normalized callable
header front end now removes one or more bounded inline decorator prefixes, including
decorators with arguments, before applying the shared method/function grammar. No new
Port, ranking lane, threshold, budget, or facade was added.

After the change, the development pack passes 4/5. Both inline decorated cases now have
1.0 file, callable, range, and source-span recall. Dense-method and same-domain cases
remain unchanged and passing. The multilingual case remains an explicit evidence gap:
with no embeddings and no learned bilingual business terms, a pure Chinese description
cannot be generically linked to a pure English identifier. Existing `learn-business`
semantics are the supported bridge; adding case vocabulary or a new retrieval
architecture would violate the stop rules.

The complete 231-variant development gate remains exactly 186/231 and 46/77. Every
formal check, anchor set, and hierarchical metric matches the accepted baseline, so
there is no pass-to-fail regression. The million profile passes with one million
searchable entities, three million edges, and a 2.26 GB SQLite database; callable-pool
P95 is 8.213 ms and large-method incremental refresh P95 is 2,278.093/5,000 ms.

Focused tests pass 58/58. The full restricted suite passes 803/805, with only two local
loopback server tests blocked by sandbox socket policy; the complete loopback module
passes 3/3 with local permission. Python compilation, all evaluation JSON, diff hygiene,
exactly four Skills, and the 500-line Python limit pass. No consumed holdout was read,
modified, or rerun.

### Serving contract correction

A follow-up architecture audit found that `hierarchical_localization` was still labeled
`shadow` even though its derived `callable_evidence` already focused compact code anchors
and source ranges. A controlled compact-context test reproduced that serving effect. The
provider contract is now `agent-hierarchical-localization/v2`, with `mode=serving`, an
explicit declaration that first-stage candidate recall is unchanged, and the serving
consumer named as `query_handoff.callable_evidence`. The separate callable evidence-set
provider remains shadow-only and does not affect compact output.

This correction changes metadata, evaluation attribution, tests, and documentation only;
it does not change retrieval, ranking, thresholds, graph depth, or budgets. Relevant tests
pass 75/75. The restricted full suite passes 805/807; the two loopback-only errors pass
3/3 outside the socket-restricted sandbox. The million profile passes at one million
searchable entities and three million edges, with callable-pool P95 7.322 ms and one-hop
owner P95 5.263 ms. Compile, 113 evaluation JSON, diff, exactly four Skills, and the
500-line gate pass. No consumed holdout was read, changed, or rerun.
