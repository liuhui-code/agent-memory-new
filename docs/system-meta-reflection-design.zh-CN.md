## 2. 触发决定

由宿主 Agent 提供真实任务边界、信号与当前用户约束。四个 Skill 增加条件式收尾
交接，Reflect 可调用确定性触发判断；有授权时先占位再生成。若客户端没有
task-end hook，仍通过 Agent 收尾步骤执行；未加载/遵循 Skill 时不能保证调用。
当前用户指令优先，正在执行元反思时禁止递归发起自动元反思。
后续[跨版本递归草案](system-meta-reflection-recursive-evolution.zh-CN.md)利用新的任务结果和冻结窗口
复核改进方法；它不修改这里的 v1 自动跳过、成功抽样为 0 和一次任务评审规则。

| 优先级 | 条件 | v1 决定 |
|---|---|---|
| 1 | 用户要求停止、关闭复盘，或预算不足以完成有意义评审 | 停止/跳过；不为了复盘延长被取消任务 |
| 2 | 用户明确要求元反思或系统改进评审 | 手动触发；任务未结束时明确只覆盖当前阶段 |
| 3 | 任务已完成、失败或阻塞，使用过或明确要求过 Memory，且存在具体系统信号 | 收尾触发一次；候选信号不等于已证明缺陷 |
| 4 | 无异常信号的成功任务 | v1 默认不自动评审，成功抽样率为 0 |
| 5 | 无 Memory 相关使用/请求，普通空结果、分页、截断或预期时效保护 | 不独立触发；必要事实可留给已触发的任务级评审 |

系统信号包括：Memory 操作失败；用户纠正其结果或使用方式；亲自核对到返回
证据与来源矛盾；至少两个真实查询轮次在同一已命名缺口上未取得新可检查证据。
仅最终任务失败不能证明 Memory 有错，信号的后续归因仍可能是 Agent 使用或
业务任务本身。成功任务可手动评审；未来非零抽样须有固定规则和可靠任务身份，
不能让模型看到结果后决定样本。

任务身份优先使用宿主真实 ID。Agent 可为实际当前任务分配会话内关联键，标记
为 `client_local`，并沿用到重试和修订；它不证明前瞻入组或统计独立性。无法
保持关联时跳过自动评审，手动评审可带缺口进行。元反思本身及其修复工作不递归
生成自动评审，用户显式要求检查元反思机制时另按手动范围处理。

## 3. 初始预算与失败语义

以下是本次设计选定的保守初始值，未经实测调优。显式 --claim 在稳定任务身份下
约束一个自动评审名额，writer 检查输入字符、引用、断言及提案数量；这不认证
任务身份或模型实际执行。未占位时的次数、重试及模型输出预算仍由 Agent 指令
约束，不证明宿主实际遵守。更严格的用户/宿主预算优先。

| 项目 | v1 决定 |
|---|---|
| 自动评审次数 | 每个逻辑任务最多 1 次；显式补充是同一评审的修订 |
| 自动重试 | 0 次 |
| 证据引用 | 整份报告最多 8 项不同引用，优先已检查材料 |
| 检查断言 | 最多 5 项 |
| 系统变更提案 | 每次评审最多 1 项；无支持问题时为 0 |
| 完整报告大小 | 最多 4,000 个 Unicode 字符，超出时优先保留问题、引用、缺口与省略计数 |
| 额外模型服务 | 不另接评审模型/API，复用当前用户 Agent |
| 元反思阶段额外工具验证 | 不为填满报告新增检查；后续候选验证按现有授权与用户约束执行 |

元反思额外 Token/耗时与原查询预算分别计量；拿不到实际数据填 null，不填 0。
收尾评审不可改写已返回的查询结果、错误状态或副作用。评审失败、截断或证据
不足分别报告，不能将其变成查询失败或功能通过。输入材料以已有可见证据为主，
不为了评审初始化、刷新、重新学习归档或重放一次查询。

## 4. 报告与提案契约

### 报告

格式标识为 `system-meta-review/v1`，约定 Agent 的评审输出及专用 `reflect-system`
输入；它不是普通 `reflect` payload 或 MCP 能力。可移植 Reflect 参考定义客户端
行为，严格输入类型及子字段见[治理记录契约](system-meta-reflection-runtime.zh-CN.md)。
以下分组均必需；未知值仅在契约允许处填 null、空列表或缺口。

| 分组 | 类型与含义 |
|---|---|
| `report_format` | 固定为 system-meta-review/v1 |
| `task_ref` | 对象或 null：实际任务键与 host/client_local 来源 |
| `review_revision` | 正整数；同一任务关联下显式修订，不增加独立任务计数 |
| `trigger`, `task_state` | 触发原因与实际任务状态；任务结束和评审结束分开 |
| `task_outcome`, `memory_use` | success/failure/partial/unknown 与 used/not_used/unknown；任务结束、结果、实际使用和模型效用判断分别表达 |
| `version_refs`, `query_refs` | 可用版本绑定对象与真实调用引用列表 |
| `observations`, `checks` | 有界事实和断言列表，引用实际材料，不保存原文转储 |
| `model_opinions` | 建议性判断、简短依据与反证；不是事实核验标记 |
| `target_components` | memory/rules/query/learn/reflect/data_model/evaluator/delivery 列表 |
| `change_proposals` | 0 或 1 项系统变更提案 |
| `missing_evidence`, `omitted_counts` | 缺口列表、已知省略数量，不冒充总体覆盖 |
| `additional_cost` | 实测额外 Token/耗时或 null |
| `review_status`, `advisory_only` | completed/partial/skipped/failed，建议性标记固定为 true |

每项检查有断言、预期依据、实际观察引用、结果和覆盖范围；结果为
pass/fail/unknown/not_run。没有执行或材料不足不能填 pass/fail。`completed`
只表示完成评审，不表示功能通过、提案应用或效能改善。文档中的空白模板可标
not_run，不能作为已执行评审记录。格式正确也不认证材料真实性。

报告不得直接写入普通 `reflect`、`update`、`experience-usage` 或
`retrieval-feedback`。尤其不能根据模型意见自动写 verified/confirmed 类标记。
只保存简短事实、身份、状态和材料引用；私有推理、原始任务/查询、日志、源码、
完整命令和工具输出转储不进入报告。默认在当前会话返回，不自动上传或发布。
仅在已获授权保存本地治理记录时使用专用 writer；它不自动脱敏、不认证材料，
也不把记录加入普通 FTS、经验反馈或排序。报告修订不可覆盖，同内容重试幂等；
同一任务沿用同一 review-key，修订和提案快照数量不代表独立任务数量。

### 系统变更提案

一项提案必须说明任务关联、目标组件、缺陷/新需求/结构演进类别、证据及缺口、
原版本与作用范围、首次可证明问题层、替代方案、目标制品、验收断言、反例、
成本边界、兼容和回退。涉及数据时增加旧新映射、迁移/回填/派生重建要求。
只支持一项机制时可以包含彼此必需的规则、代码与数据修改，不能捆绑无关优化。

Reflect 初次产生 `proposed` 或 `needs_evidence`。后续从准备到应用由维护/开发
流程推进；模型声明的状态不是执行凭证，只有 writer 返回的记录 ID 才表示该
归档中保存了记录，仍不表示提案已被批准或问题已复现。

## 5. 开发、应用与回退状态

下表描述当前生命周期。原 status writer 仍只支持 proposed、needs_evidence、
prepared、rejected 和 superseded，直接填高级状态仍返回 verification_gate_unavailable。
新增专用 accept/apply/follow-up/rollback 入口按[生命周期规格](system-meta-reflection-lifecycle.zh-CN.md)
核对执行条件；显式治理 v2 迁移后才允许这些写入，不凭模型自填状态晋级。

| 状态 | 进入条件 |
|---|---|
| proposed | 有界问题/需求与目标组件已经表达 |
| needs_evidence | 材料、复现、版本或授权缺失，明确下一项需要什么 |
| prepared | 规则差异、补丁或结构/迁移制品已准备；当前 writer 仅观察目录内 1–3 份有界文件的摘要，基线为调用方声明，不认证补丁可应用 |
| checked | 预先绑定的全部必需 v3 检查通过、产物未变且当前 Agent 逐项审查；修改制品后绑定失效，不代表外部发布资格 |
| applied | 在已有授权和兼容范围内实际应用了被检查的版本 |
| monitoring | 按事先范围观察应用版本，保留未知和退化信息 |
| closed | 已记录事先约定的关闭条件与剩余缺口 |
| rejected/superseded/rolled_back | 记录原因、关联及实际制品/结果，保留失败历史 |

用户已授权的开发副本工作可以连续推进，不需每一步重新确认。检查被跳过时
可以准备制品，但不能进入 checked 或宣称可发布。安装副本应用、数据迁移和
上游发布分别使用其实际授权；反馈许可本身不包含这些写入许可。
状态更新须带预期修订号和说明，并原子追加审计事件；报告内的初始提案快照
保持不变，当前状态以维护返回的 state/state_revision 为准。

缺陷修复、需求变更、架构变化和评测器修订分别遵守
[现有变更政策](evaluation-and-change-policy.md)。不补造 Oracle，不调整已消费
holdout；证据不足停止受影响的改动，保留可独立完成的授权工作。

## 6. 数据结构演进与协议兼容

数据结构是与规则、查询、学习、反思并列的改进目标，包括运行时对象、SQLite
表/字段/实体身份、派生索引/关系以及 JSON 投影。结构提案要有表达缺口及替代
方案；新抽象仍需满足至少两类独立缺陷的政策条件。

必须给出旧新 Runtime 对旧新数据的读写支持矩阵、字段/身份与引用映射、数据
保留断言、迁移与回填幂等/检查点、初始化触发边界、派生重建和中断恢复。
备份恢复需要覆盖迁移后新写入；代码回退、数据恢复、前向修复分别设计，不能
将一次 SQL 或恢复旧脚本视为已经完成可靠迁移。

同一版本仅增加元反思或未来 MCP 入口时，等价输入与状态下业务查询应等价。
新版本可以按事先声明目标改进命中/排序/提取结果，同时保留既有入参、缺省、
输出字段类型、状态、来源和预算语义。破坏性变化显式版本化并提供升级路径。
Runtime、Skill/规则、协议、提取器和数据版本分别绑定；不凭一个版本号推断全兼容。

## 8. 验收设计与后续实施

沿用总体方案 MR01–MR17，另增加以下触发专用场景。第 9 节记录其中机制的合成
回归结果，不将这些完整验收场景整体标为通过；未生成真实用户任务或评测包。

| ID | 场景 | 预期 |
|---|---|---|
| TR01 | 用户在任务中途明确请求评审 | 手动触发，准确标注当前覆盖范围，不伪称任务结束 |
| TR02 | Memory 相关任务收尾且有具体信号 | 按关联任务评审一次，信号不直接成为缺陷或已验证反馈 |
| TR03 | 普通空结果/截断/时效保护，或无异常成功 | 不独立触发；成功自动抽样默认 0，不声明未评审即无问题 |
| TR04 | 宿主 ID、会话内关联键、关联丢失 | 分别保留来源与保证范围；无法关联时停止自动路径，不制造独立任务 |
| TR05 | 重试、显式修订与元反思自身执行 | 自动次数不增加，不递归；修订沿用原任务/评审关联 |
| TR06 | 用户取消、跳过验证、额外预算耗尽 | 按当前指令停止/跳过或仅整理已有证据，不新增检查或标通过 |
| TR07 | 引用/断言/提案/字符预算超限 | 保留关键事实与缺口，明确省略；不自动重试或截断后声称完整 |
| TR08 | Skill 未安装、未加载、参考缺失或无 hook | 如实报告可用能力，不假设触发或持久化已经发生 |
| TR09 | 系统评审与普通经验保存同时出现 | 系统报告不进入常规记忆/排序；普通任务经验使用原有路径并保持事实边界 |

另已编写[独立治理回归用例](../tests/test_system_evolution.py)，覆盖惰性表、检索
隔离、幂等修订、严格输入、乐观状态更新、制品摘要和失败时的状态/事件边界。
它们是合成机制用例，已在临时归档运行，不属于真实活动或完整验收场景。
另有[触发/名额回归用例](../tests/test_system_evolution_triggers.py)，已执行合成
