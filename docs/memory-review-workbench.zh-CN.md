# 本地记忆审查工作台

工作台解决持续增长的记忆库缺少人工浏览、逐条核对与批量整理入口的问题。
通过既有 `tools/agent_memory.py` 启动，直接读取当前项目 SQLite；Vault 继续作为派生镜像。
它是人工维护界面，不替代四个 Skill，也不修改 Agent 的 `context` / `query_handoff` 协议。

## 启动

在已经安装 Runtime、初始化记忆库的项目中运行：

```bash
python3 tools/agent_memory.py review-ui --project . --open
```

使用自定义或集中存储的 Memory Home 时，显式指定原有位置：

```bash
python3 tools/agent_memory.py review-ui \
  --project /path/to/project \
  --memory-home /path/to/existing-memory-home \
  --open
```

- 只监听 `127.0.0.1`，默认选择空闲端口，终端显示 URL、项目和数据库路径。
- `--port 8765` 可以指定端口；省略 `--open` 时手动打开终端中的地址。
- Python 3.9+ 即可，不需要 Node、npm、外部字体、CDN 或额外服务。
- 前台运行，`Ctrl+C` 结束。不开机自启、不安装后台守护进程、不调用大模型。
- 启动和查看不初始化数据库，不安装元反思组件或执行迁移。找不到归档会提示先初始化。
- 安装器复制整个 Runtime 包，因此安装副本包含同一套页面与功能。

## 浏览与审查

左侧按记忆类型切换，中间搜索与分页，右侧显示记录内容、来源、依据、状态和原始字段。
窄屏上通过类型下拉框筛选，详情显示为可关闭的侧面板。

| 区域 / 条件 | 含义 |
| --- | --- |
| 记忆库 | 事实、反思、经历及文件 / 符号 / 日志索引；归档记录单独查看 |
| 待审查 | 尚无 `reviewed_at` 的有效 / 过期事实、反思、经历 |
| 低置信度 | 置信度低于 0.6 的有效 / 过期事实、反思；不自动判断内容错误 |
| 已审查 | 有人工审查时间的有效 / 过期记录；不等于验证通过或批准 |
| 归档区 | `status=archived` 的事实、反思与经历 |
| 搜索 | 在所选类型的主要内容、来源 / 路径等字段做字面子串匹配，支持中文及 `%` / `_` 字面量 |

搜索属于人工浏览，不复用或调整 Agent 的召回、相关性排序、诊断或评测行为。
每页 30 / 50 / 100 条，可按时间正序 / 逆序浏览；分页使用绑定当前筛选条件的游标。
同时间记录用类型与 ID 稳定区分，不将全库加载到浏览器。浏览中的并发新增或更新可能改变后续
页面；刷新回到第一页重新读取，不承诺跨请求的冻结快照。
单条详情中超长字段最多展示 64,000 字，并显式标记截断。

顶部库内记录数包含六类记录及已归档内容；列表的“匹配”数按当前筛选计算。
系统元反思提案、不可变轮次 / 交接账本、评测与历史事件不在本工作台的可操作范围内。

## 人工操作

所有操作只作用于当前项目；可以逐条操作，或选择本页最多 100 条可操作记录。
切换筛选、搜索或页码会清除选择，不支持不经核对地选择全库。

1. **标记已审查**：只记录人工审查时间，保留原状态、内容和置信度。过期记录不会因此变有效。
2. **归档**：保留内容，将状态设为 `archived` 并记录审查时间。既有常规检索按原规则排除归档记忆。
3. **恢复为有效**：仅允许已归档记录；明确设为 `active`、记录审查时间，并清除旧过期标记 / 原因。
   恢复前需由人判断内容是否仍然适用，不由界面推断原先状态。
4. **永久删除**：仅允许已归档记录。确认窗口列出选中记录，并要求输入“永久删除”。
   先备份整个 SQLite，再原子删除所选内容、对应 FTS 行与直接图关系，更新图计数 / 修订。
   不删除历史事件、历史 ID 引用、其他项目或来源文件。

批次携带每条记录的完整行摘要。在 `BEGIN IMMEDIATE` 内核对摘要与合法状态；任意一条被 Agent
或另一个窗口修改、移除或状态不符，整批拒绝，刷新后重新审查。此摘要防止旧页面覆盖新记录，
不认证审查者身份或内容正确性。

源码生成的文件、符号、日志索引仅供查看。通过既有 `learn` / `maintain-refresh-scope` 更新，
避免手工删除索引片段而破坏学习范围与索引代次。

## 备份与镜像

永久删除前的备份位于当前归档下：

```text
runtime/review-backups/before-delete-<unique-id>.db
```

备份覆盖删除前已提交的完整数据库（含 WAL 中已提交内容），文件权限为 `0600`。
备份目标在发布前切换为 DELETE journal 模式，检查完整性并清理临时旁文件，形成可独立只读打开的单文件。
备份复制发生在写者锁期间，使用独立只读连接；失败、超时或完整性检查不通过时不执行删除。
备份路径显示在页面结果提示中。归档内容可以直接恢复；永久删除不提供界面撤销。
如确需从整个备份恢复，须停用写者，并独立处理当前数据库及 WAL，避免覆盖后续有效写入；
工作台不会自动用旧整库覆盖现库。

归档、恢复、删除后 SQLite 立即更新；旧 Obsidian 文件不自动重写。完成一批整理后重新导出：

```bash
python3 tools/agent_memory.py vault-export --project .
```

自定义归档须携带同一 `--memory-home`。备份、历史引用及已导出的文件可能保留原内容，永久删除
不是全介质隐私擦除，也不自动执行 `VACUUM` 或承诺立刻缩小数据库文件。

## 本地接口边界

只服务三个固定静态资源与项目内的浏览 / 操作接口，不提供任意文件、SQL 或 shell 执行能力。
校验当前 loopback Host、Origin 与 Fetch Metadata；写请求还须携带本次启动的会话 Token、JSON
内容类型及受限请求长度。页面不渲染记忆中的 HTML，也不加载远端资源。
这是单机人工维护入口，不提供公网、多用户认证、角色权限或服务器部署合同。

分页限制的是返回量和浏览器占用。当前字面搜索与精确计数仍可能扫描大量记录，未证明百万级库
的时延目标；不会为此改变 Agent 的检索路径或自行增加常驻索引服务。

  tests.test_review_library tests.test_review_server

接口测试需要允许本机端口绑定；限制网络监听的沙箱需授权本次隔离测试。
覆盖分页无重复 / 缺漏、筛选 / 中文搜索、项目隔离、审查 / 归档 / 恢复、并发冲突整批回滚、
删除前备份 / FTS / 直接图关系清理、写入保护、安装副本及既有查询协议结构。
结果属于开发验证，不代表真实任务收益、内容有效性或外部晋级。
