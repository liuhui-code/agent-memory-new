### N16 格式口径与独立预期（未执行）

本次理论契约将上限明确为原始 UTF-8 字节：整文 65,536 字节；frontmatter 从
文件第一个字节计至闭合分隔符行结束，含 BOM、首尾分隔符及实际 LF/CRLF 字节，
最多 4,096 字节。闭合行无换行时计至末字节，但无后续正文仍不合格。闭合行必须
位于开启行之后 48 个物理行内，包含闭合行、注释和空行；源文件开启行为第 1 行，
因此闭合行为第 49 行或更早。裸 CR 和 Unicode 段落分隔符不额外分行。

以下独立预期只用于以后生成受控输入。除最后一个前缀截断变体外，类型标记须
位于前缀中已完整读取的行，其他字段和正文满足契约，且没有同时触发别的超限。
本轮没有生成这些输入、摘要或运行结果。

| 变体 | 预先固定的条件 | 预期分类 |
|---|---|---|
| N16-01 | 无 BOM、LF，frontmatter 含闭合行换行恰为 4,096 原始字节 | 可解析；不因随后正文而把头部计为超限 |
| N16-02 | 同条件下 frontmatter 为 4,097 字节 | 格式问题，不索引为完整规范文档 |
| N16-03 | 在 N16-01 同一头部前增加 3 字节 UTF-8 BOM，头部变为 4,099 字节 | 格式问题；去 BOM 不降低原始计量 |
| N16-04 | 含 BOM 的头部总量恰为 4,096 字节 | 可解析；BOM 不增加物理源行 |
| N16-05 | 将恰为 4,096 字节的 LF 头部改成相同文本的 CRLF，实际头部因此超限 | 格式问题；不能按归一化文本放行 |
| N16-06 | 闭合分隔符位于源行 49，并另有正文 | 可解析；正文起始定位为源行 50 |
| N16-07 | 闭合分隔符位于源行 50 | 格式问题；空行或注释不能从计数中扣除 |
| N16-08 | 完整原始文档分别为 65,536 和 65,537 字节 | 前者可解析，后者为格式问题；不得存入截短的正文快照 |
| N16-09 | 在正文行内部放入 Unicode 段落分隔符，物理 LF/CRLF 未增加 | 摘录源行号不因该字符而增加；原始摘要仍含其字节 |
| N16-10 | 唯一候选类型行被第 4,096 字节截断，没有完整行可确立类型标记 | 不凭部分行进入规范性解析；保留普通 Markdown 路径 |

这些变体的预期已由明确的原始计量与物理行规则给出，执行状态全部仍为
`not_run`；定义完成不等于边界已通过。执行前还须固定实际输入字节与可还原的
实现版本。已有旧解析缓存应通过不带 `--changed-only` 的既有 Scope 刷新重新
解析；不能只重建 FTS 就认定旧文档符合新口径。
