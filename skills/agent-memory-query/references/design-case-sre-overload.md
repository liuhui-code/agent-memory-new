# Google SRE：请求数量不等于工作成本

案例 ID：`sre-resource-admission`。类型：工程实践章节，不是一个新实验的结果。
查阅于 2026-11-18；使用章节原则，不复制原例中的数值或基础设施规模。

## 来源事实

章节讨论以资源衡量容量：不同请求的 CPU 成本可能不同，固定请求数难以准确代表负载。
服务端拒绝请求本身也消耗资源，客户端节流可使部分请求在到达后端前失败，减少这类压力。
见 [Google SRE：Handling Overload](https://sre.google/sre-book/handling-overload/)，
重点为资源容量、每客户限制和 Client-Side Throttling。

## 可借鉴的判断与代价

以下为迁移分析：在接受工作前说明容量和超限结果，同时核算排队、拒绝、重试的成本。
拒绝、延后或降级都把代价交给某个使用者，不能只让服务端指标变好。
资源模型需要真实负载支持，不能从“小请求通常很快”推导大输入也安全。

## 匹配与失配

- 匹配：调用成本不均、突发排队或无效重试会干扰正常工作。
- 未知：输入字节/条目、CPU、内存、等待时间和重要性的实际分布。
- 反例：低频本地任务无需照搬分布式节流设施；重要写入不能静默丢弃。

## 本项目迁移假设

大型记忆库的分页数、正文大小、源码解析量和报告成本应分别考虑，单一条目上限不足以证明总代价。
可先核对既有预算和可观察超限行为，不预先引入队列或新排序。
用代表性工作量检查交互与完整性；没有测量时保留性能未知。
