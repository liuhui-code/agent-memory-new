# Cloudflare 2019：模拟规则仍然消耗真实资源

案例 ID：`cloudflare-waf-2019`。类型：厂商对 2019-07-02 事故的公开复盘。
查阅于 2026-11-18；报告中的后续计划不当作已独立验证的完成结果。

## 来源事实

Cloudflare 报告 WAF 规则的正则回溯耗尽服务 CPU；模拟模式不阻断请求，但仍执行规则。
复盘还列出资源保护被移除、测试缺少 CPU 识别能力、非紧急更新未分阶段发布等共同因素。
见 [Cloudflare：Details of the outage on July 2, 2019](https://blog.cloudflare.com/details-of-the-cloudflare-outage-on-july-2-2019/)，
重点为模拟运行说明、What went wrong 和后续措施。

## 可借鉴的判断与代价

以下为迁移分析：规则或配置也能执行昂贵工作。“不改变输出”只限制一种行为，
不能证明 CPU、内存和故障传播没有影响；行为检查之外还要考虑工作上限与发布范围。
更严格的执行机制可能限制可表达内容，分阶段发布与回退也有维护成本。

## 匹配与失配

- 匹配：动态规则、解析表达式或观测逻辑位于重要路径，且更新影响面较大。
- 未知：最坏输入成本、保护是否有效、回退所需依赖及恢复时间。
- 反例：不能把这起事故当作当前解析器存在同类缺陷的证据，也不据此禁止所有正则。

## 本项目迁移假设

影子分析、来源读取和元反思验证也要说明执行成本和影响范围。
本案例不能驱动当前 Runtime 的猜测性改造或自动部署；发现本项目问题仍须独立受控复现。
若实际变更涉及执行机制，检查最坏输入与失败恢复，而非只确认正常输出。
