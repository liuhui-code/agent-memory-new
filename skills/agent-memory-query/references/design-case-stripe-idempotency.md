# Stripe API v1：身份、参数与已执行结果一起定义重试

案例 ID：`stripe-v1-idempotency`。类型：官方 API 合同，不是本项目运行证据。
查阅于 2026-11-18。以下具体结果缓存语义限定为 API v1。

## 来源事实

API v1 在端点开始执行后保存首次状态码和响应，包括 500；相同键重试返回已保存结果。
同键参数不同会被拒绝，键清理后再次使用可能成为新请求。验证失败或执行并发冲突不保存该结果。
当前文档另列 API v2 的失败/部分失败重试行为，不能混用。
见 [Stripe：Idempotent requests](https://docs.stripe.com/api/idempotent_requests)。

## 可借鉴的判断与代价

以下为迁移分析：超时导致“结果未知”时，需要操作身份、输入绑定、执行边界和保留期共同决定后续动作。
每次重新造键会失去同操作识别；仅记“见过这个键”也不足以解释已执行结果。
保存失败结果可能让重试继续得到失败，重试政策必须服从实际合同。

## 匹配与失配

- 匹配：副作用操作可能重复送达，调用方因超时无法确认结果。
- 未知：身份作用域、键寿命、参数相等规则、结果保存与副作用是否一致。
- 反例：过期键、新版本 API 或跨系统不一致提交，不能推导永久 exactly-once 保证。

## 本项目迁移假设

元反思名额和完成回执可以审查“同一操作”的边界，但已有去重记录不证明模型已成功执行。
不能据此放开重试或自动调用模型。检查重复、参数变化、中断及晚到结果的实际处理，再决定是否适配。
