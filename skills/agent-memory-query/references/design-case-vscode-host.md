# VS Code：扩展能力、运行位置与按需激活

案例 ID：`vscode-extension-host`。类型：官方架构与能力文档。
查阅于 2026-11-18；文档随产品演进，不固定某个已部署版本。

## 来源事实

官方文档区分本地/远程 Node.js 宿主与 WebWorker 宿主，扩展的能力和位置要求影响其运行位置。
宿主边界服务于编辑器稳定性和交互性能，扩展通过激活事件延迟加载。
见 [VS Code：Extension Host](https://code.visualstudio.com/api/advanced-topics/extension-host)，
重点为 configurations、runtimes 和 Stability and Performance。

## 可借鉴的判断与代价

以下为迁移分析：先明确消费者需要的能力、运行环境和加载时机，再选接口与执行边界。
延迟激活可以减少无关工作；跨进程/远程边界也会带来通信、序列化、失效与兼容成本，不能免费获得解耦。

## 匹配与失配

- 匹配：同一宿主接入能力不同的扩展，或昂贵工作不应挤占交互路径。
- 未知：扩展必须访问哪些本地资源，能接受哪些延迟，失败由谁隔离和报告。
- 反例：单个简单函数无需据此引入 RPC；宿主划分也不证明每个扩展都有独立安全沙箱。

## 本项目迁移假设

可借鉴 Agent 负责判断、Runtime 提供证据的职责划分，以及 Skill 参考按需读取。
这不是新增扩展进程、后台服务或 Agent 专属包装器的依据。
检查使用者是否只依赖稳定能力、未使用的资料是否被加载，以及边界失败时是否仍有可解释的结果。
